# 智调鸿枢测试环境与运行说明

## 1. 交付范围

本交付包用于复现“智调鸿枢：面向鸿蒙应用生态的端侧AI感知调度中间件”的构建、单元测试和演示流程。核心产物包括：

- `entry-default-unsigned.hap`：HarmonyOS NEXT 原生购物助手演示应用。
- `scheduler.har`：与业务界面解耦的调度中间件。
- `shopping-assistant`：去除缓存、构建目录和密钥后的源码快照。
- `构建与测试.ps1`：Windows 环境下的一键测试与构建脚本。
- 单元测试结果和覆盖率报告。

## 2. 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| IDE | DevEco Studio，包含 Hvigor、OHPM 和 Node.js 工具链 |
| HarmonyOS SDK | 6.0.2(22) |
| 目标设备 | Phone 模拟器，或兼容 6.0.2(22) 的 HarmonyOS NEXT 真机 |
| Node.js | 22或更高，仅可选云端代理需要；可直接使用 DevEco Studio 内置 Node.js |
| 权限边界 | 无需 root，不修改系统内核，不刷写系统镜像 |

## 3. DevEco Studio运行

1. 解压提交包，使用 DevEco Studio 打开 `03-源代码/shopping-assistant/apps`。
2. 等待 OHPM 同步完成，确认 `entry` 和 `scheduler` 两个模块可见。
3. 选择 `entry` 模块及 Phone 目标设备。
4. 首次运行时，由 DevEco Studio配置调试签名并安装应用。
5. 进入首页执行图片识别、文字检索或后台索引，再打开“调度显示”查看设备状态、任务状态、模型档位、线程数、后端偏好、队列动作和原因码。

交付的 HAP 为未签名构建产物，不能直接替代团队证书。比赛安装包应在提交方 DevEco Studio 中配置自动签名或正式证书后重新构建。HAR 可作为本地依赖集成到其他 HarmonyOS 工程。

## 4. 真实状态与调试状态

应用启动后默认由 HarmonyOS 公开 API 更新状态：

- `batteryInfo`：电量和充电状态。
- `thermal`：系统热等级及回调。
- `hidebug`：系统/应用 CPU 使用率与内存信息。
- Ability 生命周期：前台与后台状态。
- 调度服务：队列深度、近期时延和运行指标。

真实执行器未完成硬件探测时，默认仅声明 CPU 可用。NPU、NNRT 或 GPU 只有在执行器初始化成功并完成同模型验证后才进入可用后端集合。

调度控制台保留分组调试注入，用于组合复现实验。电量/温度组与队列/内存组可同时选择，例如“常温充电+内存高压”或“低电量+队列拥塞”。状态栏会标记 `REAL`、`MIXED` 或 `INJECTED`。点击“清除注入”后恢复系统 API 状态。

## 5. 一键测试与构建

在 PowerShell 中运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\04-测试环境\构建与测试.ps1
```

DevEco Studio 不在默认位置时：

```powershell
.\04-测试环境\构建与测试.ps1 -DevEcoHome "D:\Huawei\DevEco Studio"
```

脚本依次执行 OHPM 依赖同步、`scheduler` 单元测试、HAP 构建和 HAR 构建，并额外检查 Hvigor 日志中可能未反映到退出码的测试失败。

## 6. 建议验收流程

1. 常温、充电、资源正常：图片 Embedding 应优先高精度/4线程；文字 Embedding 和健康后台索引通常为均衡/2线程。
2. 常温充电叠加内存高压：前台图片/文字任务通常降至均衡/2线程，后台索引降至轻量/1线程并限流。
3. 高热但未临界：前台任务由效用模型综合评估，不应一律锁死为1线程；后台任务进入保护档。
4. 低电量未充电、内存临界或严重过热：触发硬保护，降至轻量/1线程，必要时暂停或拒绝。
5. 清除注入：状态来源恢复为 `REAL`，设备指标继续按1秒采样周期刷新。
6. 连续提交不同能力任务：最新任务名称、状态、调度评估数、运行中/排队数、执行耗时及失败数应随任务生命周期变化。

## 7. 可选云端大模型代理

云端回答是购物助手的可选增强路径，不是端侧调度和本地检索的前置条件。

1. 在 `03-源代码/shopping-assistant` 下将 `.env.example` 复制为 `.env`。
2. 在 `.env` 中填写 OpenAI 兼容服务地址、模型名称和 API 密钥。
3. 运行 `npm run model-search:proxy`。
4. 模拟器通过 `http://10.0.2.2:3010` 访问宿主机；真机需改为同一局域网内的电脑 IP。

API 密钥只能保存在本机 `.env` 或服务端密钥系统中，不得写入 ArkTS、HAP、HAR或提交压缩包。

## 8. 已知边界

- 未签名 HAP 需要提交方证书或 DevEco 自动签名。
- GPU/NPU/NNRT 调度结果表示在“已探测可用”前提下的计划，不等同于当前执行器已经在该硬件上完成推理。
- 组合注入验证的是策略逻辑，不可替代真机功耗、温升、吞吐和跨机型泛化实验。
- 真实设备应补充三种策略模式的同任务对照数据，并保留设备型号、系统版本、模型版本和状态来源。
