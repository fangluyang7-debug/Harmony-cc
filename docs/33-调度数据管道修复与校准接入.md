# 调度数据管道修复与校准接入

更新日期：2026-10-28。实现分支：`codex/scheduling-data-pipeline`，基于 `codex/scheduling-cloud-baseline`。

本次先修复成本反馈与准入之间的数据通道，并提供固定测试集质量评测入口。三种选择策略继续在同一构建中通过 `SCHEDULING_SELECTION_POLICY` 切换，默认保持 `CLOUD_BASELINE`。未合并或删除原实验分支。

## 审阅结论

原分析指出的框坐标导致分桶碎片化、30 秒链路寿命、手写准入统计、质量与耗时历史耦合等问题成立。另有三点需要以当前实现为准：运行时策略配置已经存在；旧样本已经写入数据库，但恢复窗口短、字段不可查询；宏观派发的 `taskHistory` 可以命中云端历史，1000 ms 是未命中时的先验，并非每次实际使用的值。

裁剪任务是否能在手机上胜过云端，需要测量端到端成本。现有手机轮询协议会增加延迟，本次没有改变轮询、SQLite 结果传输和设备 descriptor 查询，因此不会据此宣称远端性能提升。

2026-10-28 二轮修订：准入证据与新鲜度已拆开，质量评测改为按套计额度，链路跨大小拟合，耗时读取改为共享内存。评析、CANARY 配置和新能力接入边界见 [App 与终端解耦接入协议](34-App与终端解耦接入协议.md)。

## 样本与准入

新表 `RuntimeCostObservation` 保存每次反馈，包含能力、设备、执行版本、规模桶、配置摘要、测量范围、网络标识、耗时、成功状态、来源、错误类别和时间。来源区分 `BUSINESS` 与 `CALIBRATION`。保留近 30 天原始记录，过期数据由独立任务分批清理；性能估计和准入窗口分别如下。

| 用途 | 口径与窗口 |
| --- | --- |
| 各终端与云端执行成本 | `execution`，近 24 小时、同桶最近 256 条记录中的成功耗时；不按网络隔离 |
| 完整往返审计 | `roundtrip`，不作为纯执行估计；旧客户端记录不转换为执行证据 |
| 传输及协议开销 | `upload`、`download`、`coordination`、`relay-return` 分别记录；已知网络对 10 分钟，未知网络 30 秒；具体含义见文档 35 |
| 正常派发成功样本数 | 近 30 天，按能力、设备、执行版本、测量范围统计成功次数；另要求近 24 小时有成功记录 |
| 正常派发失败率 | 长期比例始终生效；近期至少 5 条时再取两窗口较大值，并检查连续失败断路器；恢复探测见文档 35 |

裁剪分桶使用输入字节数的 log2 桶、目标尺寸和 JPEG 质量十位档，去掉 `box` 与填充比例的逐请求哈希。规则由裁剪能力契约的 `costModel` 声明；未声明的能力默认只按输入大小分桶，忽略请求参数。云端、Worker 和手机共用键格式，但测量范围保持隔离。Worker 校准与正式执行使用同一执行成本键；任务历史直接按真实输入查询，移除了通配符字面量和零字节占位查找。

链路记录按设备对、网络和方向合并，不再按能力、执行版本、图片大小或裁剪配置拆桶；至少三条真实传输拟合固定时延与每字节成本。新成本键使用 `cost:v3`，旧成本桶重新积累；旧原始反馈仍可在相同能力与执行版本下参与准入统计。

成功耗时使用相同 EWMA 更新逻辑。失败记录不会初始化或刷新成功耗时；首次成功从实际耗时建立均值。统计速度时不把超时耗时掺入成功样本。手机也使用这一逻辑，结束时重新追加记录，避免多个请求覆盖一份旧聚合值。

`PLACEMENT_POLICY_JSON.sampleCount` 和 `failureRate` 不再决定派发：服务端从反馈记录重算。ACTIVE 的 `minimumSamples`、`maximumFailureRate`、`nonInferiorityPassed`、设备与能力允许列表、有效期、kill switch 和 cohort 门禁仍然有效。校准反馈不会自动批准 ACTIVE 的非劣判断。显式小流量纯任务 CANARY 可豁免非劣判断以收集速度证据，质量和授权门禁仍生效。后台指定设备校准继续豁免速度样本数量和非劣判断，仍检查实际失败率。

旧 `RuntimeCostSample` 表保留，旧聚合记录不自动转换成新准入证据：它们缺少每次执行时间、来源和可靠的测量范围。升级后需要重新积累或校准。正式服务通过 Nest 单例共享成本内存，数据库保留原始记录与准入统计；手工构造服务时，同一 Prisma 客户端共享成本库，无数据库测试可注入同一个 `RuntimeCostStore`。耗时读取不等待 `flush()`、不查数据库；每 5 秒增量同步其他进程记录，每分钟补扫近期记录，清理由独立任务分批处理。

## 网络与版本隔离

Worker 上报网络接口与地址前缀的摘要，以及 `executorVersion`。协调端将本机接口摘要和目标端摘要组合成网络对标识，接口、地址前缀变化会使用新样本桶。原始接口和地址不会存入样本表。

`RUNTIME_NETWORK_ID` 与 `WORKER_NETWORK_ID` 可作为附加网络代号，用于 VPN、出口或路由发生变化但本机接口未变化的情况；切换后应更新代号。该摘要不能感知所有网络路径变化，仍需真实传输持续修正。

手机 HAR 已提供网络采样函数，执行端心跳上报承载类型、网络句柄和接口地址前缀的摘要及执行版本。采样失败或超过 500 ms 时上报未知网络，保持短有效期。真实 Wi-Fi/蜂窝切换仍需真机验收。Worker 的 `WORKER_EXECUTOR_VERSION` 默认 `1`，实现升级时必须更新；没有可靠版本变更信号时无法自动识别同名实现变化。

## 独立质量评测

新增 `CropQualityEvaluator` 和维护命令 `calibration:quality`。命令使用 3–5 个固定样例，将云端实际 sharp 裁剪实现与目标设备输出解码为 sRGB 像素，比较尺寸和 PSNR。每个样例均通过才生成通过证据；目标设备报错或图片无效会留下失败结果。像素完全相同时，结果中的 `psnrDb: null` 表示无误差，须同时查看 `passed` 字段。

证据绑定设备、执行版本，以及包含测试集哈希、评测 ID、阈值和有效期的策略摘要。切换策略或执行版本后，旧证据不再匹配；同一策略的最新失败评测会撤销通过状态。裁剪必须配置 `CROP_QUALITY_POLICY_JSON` 并取得有效结果；全局 `qualityPassed` / `qualityVerified` 不再提供质量批准。其他能力的评测器注册和逐项人工审批见 [文档 35](35-终端测量与能力质量准入修订.md)。

PSNR 阈值需要用固定验证集和目标设备实测确定。仓库不提供默认生产阈值，测试中的数值仅用于程序回归。本次未实现 SSIM、embedding 余弦评测或自动选择阈值。

校准有独立的维护入口，可以在质量尚未批准时测固定输入。Worker 仍须已注册并通过认证；手机仍须配对、匹配所有者、在线并通过任务准入与结果哈希校验。该入口不向普通请求开放，也不自动重放购物任务。

### 使用步骤

1. 先执行本节末尾的数据库升级命令。
2. 准备本地 JSON 清单：`deviceId`、`ownerId`、`kind`（`WORKER` 或 `PHONE`）、`executorVersion` 和 `fixtures` 数组。每个样例包含唯一 `id`、相对清单目录的图片 `file`、裁剪 `parameters`（`box/paddingRatio/targetSize/jpegQuality`）。手机样例还需 `imageUrl`，其 HTTPS 内容必须与本地文件相同。清单使用固定测试图片，不放入业务照片。
3. 在根目录执行以下只读描述命令，取得测试集哈希：

```powershell
npm --workspace services/api-server run calibration:quality -- C:\calibration\manifest.json --describe
```

4. 配置 `CROP_QUALITY_POLICY_JSON`：`evaluationId` 为验证集版本名，`fixtureSetHash` 为上一步输出，`minimumPsnrDb` 为已确定的阈值，`minimumCases` 为 3–5，`validForMs` 为正毫秒数且不超过 7 天。服务端和校准进程须使用同一策略及数据库。
5. 去掉 `--describe` 执行校准。进程输出逐例结果和整体结论，不输出图片 URL、凭据或原图。设备执行版本必须与清单一致。成功证据落库后，候选构建和远端准入会读取它。

Worker 示例清单结构如下，实际需要补齐 3–5 个样例：

```json
{
  "deviceId": "worker-test",
  "ownerId": "测试所有者ID",
  "kind": "WORKER",
  "executorVersion": "1",
  "fixtures": [
    {
      "id": "edge-crop",
      "file": "fixtures/edge.png",
      "parameters": {
        "box": {"x": 0.1, "y": 0, "width": 0.8, "height": 1},
        "paddingRatio": 0,
        "targetSize": 512,
        "jpegQuality": 90
      }
    }
  ]
}
```

`RuntimeCalibrationQuota` 分开记录速度与质量额度：每个用户与设备每天最多 5 次速度校准、2 套质量评测，每套最多 5 个固定样例。失败也消耗额度；质量评测中的样例不重复扣速度额度。配额通过数据库条件更新原子领取，服务重启不恢复额度。窗口按 UTC 日期切换，即北京时间每天 08:00。版本更新仍使用同一日额度，次日可重新校准。

## 升级与回归

新增迁移 `000012_runtime_cost_observations` 创建原始反馈、校准配额、质量证据三张表及索引。根目录执行：

```powershell
npm --workspace services/api-server run prisma:generate
npm --workspace services/api-server run db:init
npm run api:build
```

本次开发验证只操作测试临时数据库，没有执行现有本地或线上数据库升级，也没有部署服务。上线时需先建表，再启动新版服务。

已验证后端全量单元测试，覆盖换框复用、测量范围隔离、首次失败不污染均值、时间窗口失效、并发追加反馈、真实样本准入、真实失败率、配额持久化与固定测试集质量证据。HTTP Worker 回归使用真实 Worker 进程、临时数据库和实际图片，检查质量证据接入后的多阶段派发。

下一阶段仍需处理：手机长轮询或事件通知、结果 artifact 化、设备目录缓存替代同步 descriptor、HAR 性能分位数与模型驻留上报、数据所在地表达、P90 可行性与分层估计。当前输入规模仍以压缩字节数分桶，像素数、后端和工作量模型可进一步细化。

真机 A/B 应使用同一构建切换策略，保持起始样本库、质量策略、设备及网络条件一致，并分别记录冷启动、校准后、网络切换、云端不可用等场景。手机网络切换和 PSNR 阈值尚未进行真机验收。
