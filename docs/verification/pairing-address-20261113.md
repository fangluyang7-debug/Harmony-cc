# 换网后的协调中心配对修复

实测环境：鸿蒙电脑 192.168.104.208，手机 192.168.104.44，Windows 192.168.104.42。

## 原因与修复

Windows 已发现协调中心，但配对出现 ERR_TLS_CERT_ALTNAME_INVALID；手机出现 TLS_CERTIFICATE_REJECTED。鸿蒙协调中心持久化证书仍包含旧网络地址。二维码邀请有效期与 TLS 请求校验独立，因此二维码未到期也会连接失败。

协调中心新生成的证书保存 IP 地址列表，启动时发现当前地址不在列表（包括旧版无地址元数据的证书）便更新证书，并提示重新配对。保持协调中心数据库及 ID。二维码增加剩余秒数与到期清除。Windows 多网卡发现按各 IPv4 网卡的子网广播，保持原发现协议；固定证书模式以已确认指纹验证，公共证书模式仍验证主机名。

## 验证

- HAR 与已签名协调中心 HAP 构建成功，安装到鸿蒙电脑。
- 原生协调中心测试与 Windows 网卡发现测试合计 44 项通过。
- 读取实机新证书，SAN 含 192.168.104.208；启用标准 CA 与主机名校验请求 /v2/identity 返回 HTTP 200，epoch 17。
- 手机重新配对成功，显示已连接、前台贡献；中枢额度为 CPU 11 槽位、RAM 11200 MiB。本机总 RAM 11591 MiB。
