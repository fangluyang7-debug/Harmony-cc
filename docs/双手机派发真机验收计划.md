# 双手机多设备派发真机验收计划

更新：2026-09-29。目标分支：`codex/cixin-multi-device-runtime`。本文记录验收起点与待验证项目，不把本机进程测试视为双手机验收。

本页“当前基线”保留动工前的状态；后续公网双机合成任务的实测结果与未通过的正式购物派发项目，见《鸿蒙作品真机验收测试说明》第 10 节。

## 实施与验收顺序

1. 固定手机 A 为发起端、手机 B 为执行端，保留 A 上原版 App；若需安装，使用独立测试包并分别记录两台手机的包名、签名、版本和 SHA-256。
2. 在手机 B 实现与现有 worker 协议兼容的真实端侧执行器，首个能力限定为 `image.crop.v1`。设备描述、输入摘要、owner 校验、租约与 fencing、取消后的物理结算、重启回执都要有可观测证据。不能将电脑上的 Node 进程冒充手机 B。
3. 建立受控的 A/协调端到 B 的通信路径，验证身份鉴别、传输加密、断连/重连与撤销。公网云服务不能直接使用手机私网地址；可先用本机调试链路验收真实计算，再决定上线用的可信中继或连接方式。
4. 用相同输入比较手机 B 裁剪输出与云基线的内容摘要和尺寸；校准不少于三轮，记录上传、排队、计算、下载耗时与样本有效期。无真实样本时只允许 OBSERVE/SHADOW。
5. 开启受限 CANARY，核对任务发起、候选设备、选择理由、租约、执行回执、结果返回，确认计算确实发生在手机 B；断网、取消、超时、低电量、后台、锁屏、重复派发和执行器重启分别演练。
6. 验证门禁回退：撤销手机 B 或触发 kill switch 后新任务回到合法云基线；旧任务按回执确认物理停止或保留未结算状态，不以超时响应冒充停止完成。

## 通过标准与留证

- 同一任务的运行 ID / attempt ID 可在发起端、协调端和手机 B 的脱敏日志中对应，且手机 B 的执行回执与输出 hash 一致。
- 至少三次真实图片裁剪成功；失败场景有明确错误码和恢复结果。线上购物检索是否可用另测，不能用裁剪成功代替。
- 记录两机型号、系统版本、App/HAP 摘要、服务端提交、策略版本、网络条件及每轮耗时；性能收益只以同条件实测报告。
- 每次真机步骤在验收记录中标为通过、失败或未执行，附时间与证据位置。

## 当前需要用户协助

- 两台手机保持解锁、亮屏、USB 调试授权和可上网，调试期间允许独立测试包安装及必要的网络权限弹窗。
- 确认哪部作为日常使用手机；默认 `MIS-AL00`（A）发起、`ADY-AL00`（B）执行，避免误覆盖已有 App。
- 真机需要手动操作或手机系统弹窗时，按提示完成并反馈；不需要在聊天中发送密钥。

## 2026-09-29 首轮双手机联调实录

- 两机均安装独立测试包 `Micro.12.myapplication.codextest`。最终验收 HAP SHA-256：`7A82B641CEEF6FF34580A723A334FFFF518710847A804B5CC485677EF51E9C0A`。原版包未改动。DevEco `assembleHap` 成功。
- 本轮使用 `apps/harmony/monitor/dual-phone-lab.mjs`，只绑定电脑 `127.0.0.1:8766`。HDC 反向端口：B 的 `8766 → 电脑 8766`，A 的 `8767 → 电脑 8766`。两机只通过 USB 调试隧道访问协调器，不对公网或局域网开放实验接口。
- A 在 App 内提交 512 条、每条 8 维的合成向量；B 的同一 App 页面接取租约并执行 `Math.hypot`，将计算结果回传。任务 ID：`b30fb0ee-98d4-47f4-b86e-64909a69aa59`。A 显示“**双机任务完成，结果已校验**”，B 显示“**本机计算与协调器复核一致；512 条向量，7 ms**”。协调器记录 `state=COMPLETED`、`workerId=phone-B`、输入摘要 `b06d7c13a7a08ab75eb4b0f3ce03311729e6fa4bb7fecfa29e4038f5cfbc9a20`、输出摘要 `d42c66a558dffc54262f58e0675cf797ad0403b7335b0313c0ccdf268c215a26`。该耗时为手机自报的计算段时长，**不是端到端性能收益**。
- 最终 HAP 复测：任务 `25dd502d-ef7c-493c-a523-6551c42c0ae5`，A 显示“双机任务完成，结果已校验”；B 显示“本机计算与协调器复核一致；512 条向量，8 ms”；协调器 `state=COMPLETED`、`workerId=phone-B`，输入/输出摘要与首轮一致。B 停止接取后，A 提交任务 `641c5fdc-2f90-44c0-82bf-411dabcd996c` 并点击取消；A 显示“已请求撤销；迟到回执将被拒绝”，协调器状态为 `CANCELLED`，`workerId=null`。此例是**接取前取消**，不能证明运行中的计算已物理停止。
- 协调器协议测试通过：无效令牌拒绝、错误输入拒绝、正确结果确认、重复回执拒绝、撤销后迟到回执拒绝；`git diff --check` 通过。取消测试目前只证实协调器撤销租约并拒绝迟到结果，**未证实手机计算在取消时物理停止**。
- **验收边界**：这是 USB 隧道上的真实 A→协调器→B 计算闭环，能力是合成向量归一化实验。协调器的 `workerId=phone-B` 是测试客户端声明的身份，结合 HDC 对 B 页面的操作和状态观察可确认本轮执行位置，但尚无生产设备证明或账号绑定。尚未把手机 B 接入 Zeabur 的 `DeviceDispatchService`，也未完成正式购物工作流、图片裁剪、端侧后台保活、无线断连恢复、生产鉴权及 CANARY 门禁验收。不能把本轮结果写成公网多设备派发已上线。

## 复现实验

在 `harmony-agent` 目录运行 `node apps/harmony/monitor/dual-phone-lab.mjs`，从本机终端读取本次随机配对码。使用 HDC 给 B 设置 `rport tcp:8766 tcp:8766`，给 A 设置 `rport tcp:8767 tcp:8766`。两台手机打开独立测试包的“我的 → 双机派发联调”，输入同一配对码；先在 B 点击“开始接取”，再在 A 点击“派发任务”。结束后可在 A 查询任务状态，在 B 停止接取；重启协调器会清空内存中的实验任务和轮换配对码。该工具只供 USB 本地联调，不应部署到 Zeabur 或开放到公网。

## 接入正式调度链路的剩余改造

现有 `DeviceDispatchService` 通过 HTTPS 主动请求 Node worker；手机通常没有可由 Zeabur 直连的公网监听地址。正式接入应改为 B **主动连接 Zeabur** 的受保护设备通道，而不是把本机实验服务暴露到公网。

1. 服务端增加账号归属明确的设备登记与配对流程，设备凭证独立于用户 JWT，可撤销、轮换；手机 B 的身份不能只依赖客户端自报的 `workerId`。
2. 将可派发任务、工件、租约、fencing token 和回执存入持久层。B 通过出站 HTTPS 拉取任务、领取租约、提交结果；取消需由 B 确认执行线程结束，未确认时保留占用状态。断线和服务重启后要按持久回执恢复，不能重复提交业务效果。
3. 在 B 实现正式能力适配器，至少完成与云端一致的 `image.crop.v1` 输入校验、尺寸/质量输出与摘要验证；合成向量实验结果不能代替图片购物链路验收。
4. 将手机适配器纳入 `DeviceDispatchService` 的设备池及灰度门禁：真实质量校准、上下行数据传输与计算耗时样本、设备温度/电量/前后台状态、隐私授权和 kill switch 均满足要求后才允许 CANARY。
5. 两手机重复验证同一购物任务的候选设备、派发决策、B 执行回执、云端后续阶段和最终结果；同时测设备撤销、断网、取消、超时、后台与重新上线。每项单独留证，不以本地联调通过替代公网验收。
