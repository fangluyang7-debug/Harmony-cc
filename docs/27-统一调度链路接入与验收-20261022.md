# 统一调度链路接入与验收

本次对照复赛架构审查文档与作品说明 PDF，沿用已有任务画像、设备状态采集、PlacementPolicy 和 ConstrainedPolicy，补接云端目录、Worker 和配对手机路径。购物 App 是能力接入样例。外部 App 需要注册任务模板、能力执行器和输入输出契约，系统不会自动理解任意未接入 App 的业务代码。

## 当前执行链路

手机 ADAPTIVE 请求保留调度意图，云端根据任务图、预算、隐私授权、设备能力和实测成本选择执行位置。通用 dispatch 校验 DAG、逐节点派发、传递制品并核验 hash；节点完成后以实际输出和剩余预算重新规划未完成部分。成本门禁比较完整工作流，云端中转产生的下载与再次上传均计入成本。

Worker 接收 macroContext，由 WorkerExecutor / WorkerPolicy 在真实 CPU、可用内存和租约槽位约束下准入并选择配置。线程数用于实际计算；priority 是策略标签。取消和超时后，未物理结束的计算仍占槽位，不能提前释放后继续超卖。

配对手机通过目录进入同一候选选择，保留原 owner、租约、fence 和撤销协议。手机复用 HarmonyDeviceStateAdapter 的逐字段时间戳形成资源画像，使用现有 SchedulerClient 进行端内准入。心跳有效期与资源有效期分别检查；未知、注入或过期状态不会伪装成真实可用硬件。实际耗时按设备、输入规模和参数持久化，后续决策使用有效期内样本。

## 设备接入

1. 运行 API 的 prisma:generate 与 db:init，应用新增 RuntimeDevice、RuntimeCostSample 表。已有迁移保持幂等。
2. 在 API 环境中配置至少 32 字符的设备凭据，例如 CPU_WORKER_TOKEN；在 Worker 配置同一值的 WORKER_TOKEN。凭据内容不写入目录数据库。
3. 使用用户 JWT 与维护令牌调用 POST `/api/v1/runtime/device-directory/workers`，提交如下连接信息：

```json
{"deviceId":"cpu-worker","endpoint":"https://worker.example.test","tokenEnv":"CPU_WORKER_TOKEN","enabled":true,"qualityVerified":false,"cropPriorMs":500}
```

4. Worker 设置 WORKER_DEVICE_ID 与 RUNTIME_COORDINATOR_URL，启动后自动向目录报告资源心跳。动态目录优先于旧 RUNTIME_DEVICES_JSON；撤销和过期条目不会被旧配置重新激活。
5. 沿用校准接口获取真实计算与传输样本，经过质量验证后配置 PLACEMENT_POLICY_JSON。目录注册本身不会绕过灰度、质量、样本、收益和 kill switch 门禁。
6. 手机启用 PHONE_DISPATCH_EXPERIMENT_ENABLED，通过原配对流程绑定 owner，并在接取页运行资源上报与轮询。通用裁剪入口不再通过旧演示优先分支抢占选择；网络和隐私授权必须同时允许外发。

## 验收依据

- API：38 套件、285 项单测通过；HTTP 端到端 10 项通过；Nest 构建通过。
- Worker：3 项测试通过，包含独立 HTTP 进程、真实 Sharp 裁剪、配置应用、拒绝准入和物理结算。
- 目录集成：实际 SQLite 注册、心跳、过期与撤销；真实 HTTP Worker 从动态目录被选中；配对手机协议测试包含宏观上下文、错误 fence 拒绝、正确回执和反馈持久化。
- 协议、迁移、购物入口和放置策略回归通过；scheduler 与 cloud-shopping 类型检查通过。
- DevEco 原生 HAP（未签名）、HAR 构建成功；调度库 174 项、App 27 项单测全部通过。原生编译不等于双手机实机验收；本机 hdc 未发现连接设备。

## 能力边界

框架可以派发已注册能力组成的多节点 DAG。当前 Worker 实现 CPU 裁剪和向量归一化；手机跨设备适配实现裁剪。新增 GPU/NPU、模型或业务能力仍需对应执行器、资源来源和校准证据，不能靠枚举声明获得执行能力。

购物 12 阶段接入了阶段调度钩子，纯裁剪走通用图。数据库、模型服务和结果提交仍通过云端能力回调执行，尚未实现整个购物 DAG 一次性联合放置。云端基线的部分容量和成本仍采用声明值，需要进一步接入实时准入与测量。当前手机接取依赖页面运行，未完成后台驻留服务。上述事项与双实体设备、已部署云端的性能验收仍是后续工作，不能据本轮测试称为覆盖所有硬件的完整系统。
