# 参考文档

本文整理本聊天窗口中为 `harmony-agent` 调度件分析、设计和文档撰写时可确认参考过或写入项目文档的外部资料。范围包括论文、官方文档、平台说明和工程文档；没有把测试 URL、本地端口、用户自己的 Zeabur 项目地址、示例域名和未实际采用的链接列为参考来源。

## 一、学术论文与系统论文

### 1. Clockwork（OSDI 2020）

- 链接：https://www.usenix.org/conference/osdi20/presentation/gujarati
- 用途：用于说明“预测驱动推理调度”“模型加载、排队、执行成本分解”“可解释的推理服务调度”已有研究基础。
- 在本项目中的作用：作为调度思想参考，帮助界定本项目不能简单声称学术首创；项目重点仍是鸿蒙应用内 AI 任务、业务画像、端云链路和协作式执行。

### 2. InferLine

- 链接：https://arxiv.org/abs/1812.01776
- 用途：用于参考端到端推理流水线、延迟目标和资源规划相关思想。
- 在本项目中的作用：支撑“端到端成本”和“多阶段任务链路”这类表述，但不套用其服务器场景的性能结论。

### 3. Agent Workflow Memory

- 链接：https://arxiv.org/abs/2409.07429
- 用途：在 Cixin 参考资料中用于讨论从执行经历中提取可复用工作流。
- 在本项目中的作用：主要用于界定创新边界，说明“技能库/工作流复用”不是本项目可单独声称首创的点。

### 4. ReUseIt

- 链接：https://arxiv.org/abs/2510.14308
- 用途：在 Cixin 参考资料中用于讨论从执行尝试中合成带检查的可复用流程。
- 在本项目中的作用：同样用于界定创新边界，避免把通用流程复用概念写成独创贡献。

## 二、鸿蒙、OpenHarmony 与系统能力资料

### 5. HarmonyOS 开发工具与平台

- 链接：https://developer.huawei.com/consumer/cn/develop/index.html
- 用途：作为 ArkTS、ArkUI、DevEco Studio 等原生开发路线的官方入口。
- 在本项目中的作用：用于确认鸿蒙原生工程、HAR/HAP、DevEco 工具链等路线，而不是作为某个具体 SDK 能力已验证的证据。

### 6. OpenHarmony 官方架构说明

- 链接：https://docs.openharmony.cn/
- 用途：用于解释 OpenHarmony 的多内核架构、KAL 层等背景。
- 在本项目中的作用：用于回答“不同设备选择不同内核是否影响调度算法”这一问题，结论是共享调度逻辑、按设备和能力适配，不按内核名称复制多套算法。

### 7. HarmonyOS 5 / HarmonyOS NEXT 官方说明

- 链接：https://consumer.huawei.com/cn/harmonyos-next/
- 用途：用于区分 OpenHarmony 与不同代际商用 HarmonyOS，避免把 Linux/LiteOS 多内核说明无条件套到所有当前设备。
- 在本项目中的作用：提醒文档中不要泛化“鸿蒙手机一定使用某内核”，具体设备能力需按系统版本核实。

### 8. 华为 SysCap 文档

- 链接：https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V14/js-apis-syscap-V14
- 用途：用于说明鸿蒙设备能力应通过系统能力探测判断。
- 在本项目中的作用：支撑“能力探测优先于按设备/内核名称判断”的设计原则。

### 9. OpenHarmony HTTP SDK 接口说明

- 链接：https://raw.githubusercontent.com/openharmony/interface_sdk-js/master/api/%40ohos.net.http.d.ts
- 用途：核对 NetworkKit/HTTP 请求中的发送进度和 `performanceTiming` 字段含义。
- 在本项目中的作用：用于云端任务链路中手机侧上传、下载、请求耗时回传设计。
