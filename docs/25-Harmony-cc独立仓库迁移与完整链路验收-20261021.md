## 2. 完整链路保留范围

| 链路 | 保留文件 | 迁移后的关系 |
|---|---|---|
| 手机应用 | entry 全部源码、资源、页面、模型与商品样本 | 与 scheduler 保持原相对依赖 |

| 云购物客户端 | CloudShoppingExecutor、上传、网络探测、完整结果模型 | 继续通过原云配置访问服务 |

| 双手机 | 云端配对、轮询、裁剪、回执与页面 | 原演示路径和开关保留 |
| PC 展示 | monitor、双机实验、Web 调试与商品管理 | 可从本仓库直接启动 |
| 可选图像服务 | Python 服务与 requirements | 仍需自行配置原可选模型与环境 |

云端数据库、COS 和第三方模型是原链路的外部服务。迁移目录不会复制线上账户或自动迁移这些服务的数据，现有访问配置在本机保留。运行时域名中出现 `cixin` 仍表示现有服务地址，不是对 Cixin 源码仓库的依赖。

## 3. 文件保全与归档

初始复制逐文件核对 SHA-256，共 **10011 个文件、1613328417 字节**。复制使用真实文件，不使用指向旧目录的符号链接。

其中旧提交快照 **9068 个文件、1355016147 字节**，从 `提交文件/competition-deliverables` 的子目录和旧 ZIP 归入 `archive/legacy-submission-packages`。本地全部保留，Git 忽略重复源码和压缩包。正式复赛说明、测试报告、模板版本和两个演示视频保留在主线 `提交文件/复赛`。

`node_modules`、`oh_modules`、build/dist、IDE 和构建缓存、测试临时产物等可再生产目录不沿用。Node 依赖在新目录通过 `npm ci --include=dev` 重新安装；鸿蒙依赖由 ohpm 重新安装。迁移前的未签名 HAP、已签名 HAP 和 scheduler HAR 单独保留到 `提交文件/构建产物`；已签名本机包不进入 Git。

`.env`、`.env.zeabur.local`、原签名 build-profile 备份保留在本机且被 Git 忽略。原调试证书已于 2026-10-11 过期，当前 build-profile 使用便携无签名配置，安装手机前需在 DevEco 中重新签名。模板、模型资源、样本、迁移和文档进入 Git，可以用于重新构建。

## 4. 为独立仓库进行的改动

1. 根 npm package 名改为 `harmony-cc`，同步 lockfile 根身份；子 workspace 名和业务标识保持兼容。
2. 重写根 README，提供当前独立运行入口；原 README 保存在 `docs/history/README-before-Harmony-cc.md`。
3. 增加提交材料索引与 archive 说明。
4. 提供无私钥的 `build-profile.template.json5` 和 `native:prepare`；本机实际签名配置从 Git 排除。`native-check.ps1` 在缺少 profile 时先生成便携配置。
5. 增加 `standalone:verify`，检查 Git 根、锁文件、关键链路文件、仓库基线清单和本地依赖边界。
6. 将文档 24 的当前源码链接改为仓库相对位置，避免跳回旧目录。
7. 修复一条测试准备假设：`test-cloud-shopping.mjs` 原先认为默认云地址为空，但当前 App 内置演示 origin。测试显式构造空 origin 场景，保留原业务默认地址和断言。

这些调整没有改变调度策略、正式购物路由、Worker 算法或手机演示执行逻辑。
