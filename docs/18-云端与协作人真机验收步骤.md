# 云端与协作人真机验收步骤

本清单用于完成尚未通过的验收，不是成功声明。当前公网域名为 `https://cixin.zeabur.app`，内部地址 `cixin.zeabur.internal` 不能填入手机。代码位于分支 `codex/cixin-multi-device-runtime` 的 `harmony-agent`，本地未提交改动不会自动出现在 Zeabur。

## 一、提供部署诊断信息

在 Zeabur 项目打开 cixin 服务，查看源码/设置和最新部署详情。提供以下非敏感信息或对应截图：

- 连接的仓库、分支、根目录及部署 commit。
- 最近一次部署的状态；构建和启动日志末尾约 30 行。
- 服务网络映射的容器端口，当前截图为 8080。
- 持久卷挂载路径是否为 `/data`。不要复制环境变量值、令牌和密钥。

目标配置为仓库 `fangluyang7-debug/Cixin`、分支 `codex/cixin-multi-device-runtime`、服务根目录 `harmony-agent`。该目录的 `zbpack.json` 定义安装、构建和启动。服务应读取 `PORT` 并监听 `0.0.0.0`；当前公网映射要求实际监听端口与 8080 对齐。不要删除或重建现有数据库卷来排查 404。

本轮代码需先提交并发布到实际部署源，才能验收新接口。正式商品库和向量索引还需有可检索且维度相容的数据；数据库探测成功只说明表可读，不保证有商品。COS 和模型变量参考 `.env.zeabur.example`，只在服务端填写。

## 二、检查已部署版本

在 `harmony-agent` 目录执行：

```powershell
npm run api:acceptance -- --base-url https://cixin.zeabur.app --output deployment-report.json
```

脚本只发 GET；readiness 会在服务端产生少量模型请求及专用 COS 探测对象读写。报告不保存业务响应、签名 URL 或凭据；输出文件已存在时拒绝覆盖。退出码 1 表示尚未通过，0 仅表示报告所列检查通过，不代表全部真机验收通过。

- 空 404：API 尚未提供期望路由，核查部署源、域名绑定、端口和启动日志。
- 502/503：先区分网关错误与带 API JSON 信封的依赖阻断，后者需要检查数据库/COS/模型配置。
- health 成功而缺少 `shopping.stage.*` 工具：线上版本不包含本轮完整改造。
- readiness 成功后才进行手机正式任务测试。

## 四、协作人操作与取证

1. 安装本轮签名 HAP，在个人页保存公网 HTTPS 地址。
2. 输入已知存在于云商品库的文字查询，保存结果截图、任务日志、taskId 和 runId。日志应先有远程计划，再有 HTTP 执行和结果，且无正式本地索引调用。
3. 用同一已知商品照片执行图片查询，保存结果截图和关联 runId。检查云端资产、候选、价格及图片能展示。未返回商品时不要把“接口成功”当成业务召回通过。
4. 在服务重启前执行下列命令保存该图片任务的阶段与遥测检查。Runtime 历史目前仅驻留内存。

```powershell
npm run api:acceptance -- --base-url https://cixin.zeabur.app --run-id run_替换为实际ID --output image-run-report.json
```

5. 验证断网/错误地址时明确提示失败，不能显示本地商品作为搜索成功。恢复地址和网络后重新发起任务。
6. 开始图片任务后取消或发起替代查询，记录旧任务不覆盖新结果；对已到达服务端的旧任务检查取消状态。HTTP 尚未到达服务端就取消时不会有云端 run，保留手机日志说明。
7. 在隔离测试环境验证超时及依赖不可用，保存失败原因和阶段状态；不要为制造故障修改正式密钥或停止共享服务。尚无条件验证时明确列为待验。
8. 手机上传/下载耗时为 null 的情况必须记录为观测缺口；不能补成 0。服务端应有存储读写、模型/检索执行和排队字段。

交回材料：手机型号/系统版本、构建版本、文字和图片 taskId/runId、结果截图、两份检查报告及取消/失败/超时日志。不要交回完整业务原始图片、密钥或签名 URL。所有材料经核对后再更新验收记录。
