## 阶段十二：反馈提问不再要求任务成功（2026-09-27）

- 用户反馈：选择题的目的是在前期获取用户感知以调整约束；等太久后用户可能直接退出，任务不一定成功，因此“必须成功才出题”会丢掉最有价值的负信号。
- 提问准入改为“这一步能否调整调度参数”：前台、非后台/预览、已授权且存在受控执行配置即可参与，不再要求 `SUCCEEDED`；无执行配置仍按 `PROFILE_REQUIRED` 排除。
- `FeedbackController` 对 `TIMED_OUT`/`CANCELLED`/`FAILED` 生成等待容忍度问题（原因码 `NO_RESULT_ACCEPTABILITY_UNKNOWN`，优先级 90），选项含“一直没出来”；成功结果题仍需 `RESULT_DISPLAYED`。
- 非成功/离页的邀请标记 `suggestedAfter: NEXT_IDLE`，保留 30 分钟；`SchedulerService` 不再在 PAGE_LEFT/CANCEL/INPUT_REPLACED 时清除非成功邀请；`SchedulerClient` 允许已结束但被取消的工作流查询/提交反馈。
- `ConstrainedPolicy.feedback` 允许等待答案在 `actualConfirmed !== true` 的超时/取消样本上参与速度维度校准（等待感受不依赖配置确认）；质量答案仍要求真实执行已确认。
- App（`Index.ets`）记录离页/取消的 workflowId，回到前台空闲时通过只读 `FeedbackAvailability` 拉取延后题；回答使用记住的 workflowId，不再依赖 `activeSearch`。
- 边界：只改通用调度 SDK 与购物示例 App，不接温度/内存/卡顿问卷；一次一题、同意/前台/所有权/有效期/日与间隔限频不变；等待答案仍为有界校准，不直接改目标时延或质量底线。等待答案在超时/取消下可为 `COLLECTING` 或 `RECORDED_ONLY`（无样本时），不虚构样本。本轮未在 DevEco 运行测试套件与真机复测。
