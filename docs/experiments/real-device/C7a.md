# C7a 两个 App 同机验证

状态：待真机，未执行。也可在 API 22 模拟器预跑，但不能代替真实 ODID、签名和设备行为。

1. 记录手机型号、HarmonyOS 6.0.2/API 22 或更高兼容系统、开发 SDK、同一开发者签名主体、PC/网络、提交与未提交差异。所有终端统一 API 22 构建。
2. 按 `apps/harmony-indexer/README.md` 构建共享 HAR、indexer 和 SoleAI，在 DevEco 的构建工程中配置合法签名，保存同一 HAR 的 SHA256、两个签名 HAP 的 SHA256。保留原应用数据，首次使用专用测试安装/身份；不得为了测试清空用户 SoleAI 数据。
3. 在隔离测试组配对手机所有者，确认其物理预算。用同一手机设备身份注册两个独立 App，分别批准 `image.crop.contract`、并发 1、CPU 1/RAM 64 MiB 及在线额度；预算总和不超过手机已确认额度。用 `app-register-main.js ... --invite-only` 保存两份一次性邀请，在对应 App 内兑换。
4. indexer 选择经授权的真实测试图片；SoleAI 打开“本机偏好 → v2 裁剪验收”，选择另一组图片。检查原图/缩略图分别在自己的沙箱，输出可解码、128×128。完整裁剪几何/颜色质量另外按 C4a 的参考评测，不能只看尺寸。
5. 两个 App 同时发起批量任务，导出协调者计划、attempt、回执及各自账本。验证独立 appInstanceId、holder、额度与输入输出权限；所有时刻 CPU/RAM 实际占用之和不超过物理预算；第三份超额预留被拒。来回切前后台，核查暂停/取消和真实结算。
6. 记录两 App 的 ODID 是否符合 X3，同开发者重装及身份变化按 X3 单独执行。当前代码依靠所有者确认绑定物理预算，不能把该人工绑定当作 ODID 自动关联已通过。
7. 模拟失联：新 v2 任务被拒；SoleAI 原 v1 入口按其原有策略工作；已提交/投递不明任务不得重做。恢复后核对旧任务与占用。
