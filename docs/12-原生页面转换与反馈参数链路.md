## 用户要求

将仓库新增三个文件夹中的手机前端 HTML 转为鸿蒙 ETS，并完善“问题回答 -> 参数调整”。继续遵守文档 09 的完整配置包、应用解耦、质量底线、四阶段模式和反馈授权/限频，不把静态成功提示视为真实优化。

## 对静态原型的调整

- 展示真实 Product.imageUrl，不把原型鞋图冒充数据集商品；图片缺失/加载失败时保留原生相册图标底图。外链图片仍依赖数据源和网络。
- 不虚构匹配率、实时库存、折扣、90 天曲线、3D、识图锁定率、截图自动检测或穿搭聚合。价格趋势显示暂无数据，价格与库存明确为本地记录。
- 相机图标接入系统图片选择器，只提供主动选图与预览。当前模型是文字 Embedding，图片不会偷偷转换为“运动鞋”查询；用户补充文字后执行真实搜索。未接入实时相机、语音、图像模型。
- “灵感穿搭”改为“商品”，展示本地商品。清单支持加入/移除，真实搜索历史可再次执行，二者仅本次运行保存；不虚构账号、购物车数量、物流或支付。
- 商品来源只接受 HTTPS 形式的链接，通过系统 Ability 打开，失败有提示，不自动购买。

## 回答到参数

```text
“我的”显式授权 -> 结果展示，或任务以非成功终态结束（超时/取消/失败，含等太久离页）
  -> getFeedbackRequest(workflowId) -> 限频后的单题（非成功/离页为 NEXT_IDLE 延后题）
  -> ShoppingTaskService.submitFeedback(workflowId, UserFeedback)
  -> SchedulerClient 校验工作流所有权/终态/输出节点（已取消但已结束的工作流也可提交）
  -> SchedulerService 校验同意/前台/有效期/选项/去重
  -> ConstrainedPolicy 关联版本、能力/模型、任务、状态/输入桶、实际配置
  -> 分维度有界校准 -> FeedbackReceipt -> 页面展示回执
  -> 后续决策使用校准权重，仍只选择合法 ExecutionProfile
```

新增 FeedbackReceipt、FeedbackCalibration 是通用 SDK 类型。回执包含 accepted、effect、reason、模式/版本、门槛及前后数值；telemetry.feedbackReceipt 保存独立快照，无原始业务输入输出。旧 USER_FEEDBACK 信号仍走同一接收逻辑。

| 回执 | 含义 |
|---|---|
| REJECTED | 未接收：未授权、过期、已回答或工作流不匹配等 |
| RECORDED_ONLY | 已记录：样本缺失、混合执行、旧版本，或质量答案未确认实际配置；等待答案在超时/取消下仍可进入速度维度校准 |
| COLLECTING | 已记录，同配置同维度的答案未达到门槛 |
| CALIBRATED | 达到门槛，重算后续效用系数；不代表本次重跑或已切换配置 |

当前是可解释规则校准，不是神经调度模型，也还没有实现文档 09 的满意概率曲线：

- 各维度独立取最近 observationWindowSize 条已回答样本，未回答不当作满意。
- 速度负反馈将时延代价系数从 5 调到最多 10，不放宽 targetLatencyMs/softDeadlineMs/硬截止时间；用户只看到“等待是否可以接受”，不看到内部数值。
- 按用户最终要求，不询问温度、内存或卡顿等客观状态；资源自动监测与保护保持独立。主动提问只针对等待容忍度和应用明确报告的结果质量疑点。
- 配置惩罚最多 3，取达到门槛的各维度惩罚最大值；时延和质量答案不能互相凑样本。非成功终态（超时/取消/失败）或用户等太久离页与已知超时一样先问能否接受等待，应用质量疑点其次；没有必要不提问，不为收集样本而突破限频。非成功/离页的邀请标记 NEXT_IDLE，延后到下次前台空闲展示。
- 窗口负反馈比例下降可回到基础系数；速度好评不降低质量底线。配置、版本、真实/注入状态桶互相隔离。
- 校准不修改队列优先级。OBSERVE/SHADOW 的真实配置仍为基线；CANARY/ACTIVE 仍需质量、样本、相邻转移、冷却与熔断检查。显式 preferredProfileId 规则仍优先，不承诺回答必然切换配置。

默认门槛仍为 10，UTC 日最多 2 次、同能力/任务类型每天最多 1 次、间隔至少 30 分钟；成功结果题邀请 2 分钟过期，非成功/离页的延后题保留 30 分钟。一次使用不立即个性化。样本沿用原方案仅进程内保存，普通短会话很可能长期处于 COLLECTING；没有为演示绕过限频或跨启动继承学习效果。跨会话脱敏聚合、离线先验和满意概率曲线需要后续独立设计与验收。

主机 scheduler 151 项、entry 17 项通过；保留原 137/12 项，新增 SDK 接收/校准 14 项和应用纯逻辑 5 项。包含所有权、去重、撤销后重新授权、忽略结果、旧版本、快照、分维度门槛、有界窗口、权重实际进入后续效用且 OBSERVE 配置/优先级不变。原始报告见 testing/semantic-test-result.txt 与 testing/entry-test-result.txt。

真机仍需检查：

1. 快捷搜索、输入、品牌价格约束、排序、空结果、取消/重试、高质量开关。
2. 列表到详情再返回、清单增删、HTTPS 跳转，无伪造曲线或匹配率。
3. “我的”授权后搜索出现单题；回答对应正确 taskRunId，回执与审计一致。
4. 收起/恢复、过期、改输入、换页、切后台不能造成串任务或重复计数。
5. 320/360/412 vp、横屏、大字体下的长标题、浮层拖动、输入区和键盘避让。
6. 图片选择/取消只影响当前页面，未接图像模型时不能声称按图片检索。
