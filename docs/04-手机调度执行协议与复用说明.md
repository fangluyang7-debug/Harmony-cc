# 手机调度执行协议与协作者代码复用

版本：2026-09-20。范围：当前鸿蒙 `scheduler` HAR，不涉及此芯主线代码修改。

## 来源与适配

来源提交：[Cixin 0f50f8c](https://github.com/fangluyang7-debug/Cixin/commit/0f50f8c6b8897171eaf13733fe0c8c7fb6a9d4b5)，主要参考 `shopping-assistant/services/api-server/src/core/runtime/guarded-execution.service.ts`。

| 协作者已有机制 | 鸿蒙中的对应实现 |
|---|---|
| 执行前再次准入，避免旧计划直接产生副作用 | 提交、状态改变和出队前检查策略，从注册表寻找支持最终计划的执行器 |
| 取消后等待 Handler 完成再释放执行占用 | `STOP_REQUESTED` 与最终 `CANCELLED/TIMED_OUT` 分离，等待执行器 Promise 结束 |
| 同一执行身份关联状态和输出 | 原有 taskId 继续关联状态、执行计划、结果、停止请求时间 |

这是原生适配和机制复用，不是 NestJS 源文件直接运行于 ArkTS。Linux 进程组、Node 服务模块、平台阈值与跨阶段事务协议没有搬入手机。

## 执行计划

- 排队中的计划不是最终执行承诺：状态与策略改变后可重新计算。
- 已绑定执行器收到出队后的最终计划，而不是提交时被闭包捕获的旧计划。
- 最终计划不受支持时任务失败，不伪装为已切换硬件后端。
- 手动暂停和保护策略暂停分开：状态恢复可解除策略暂停，不会解除用户手动暂停。
- 已运行的不可抢占计算不在中途重配线程；支持检查点的执行器可在分块完成后重新排队，再根据当时状态选择下一块的配置。

## 取消与超时

```text
QUEUED → RUNNING → SUCCEEDED / FAILED
            ↓ 取消或执行超时
       STOP_REQUESTED
            ↓ 执行器 Promise resolve/reject（表示其管理的工作已结束）
       CANCELLED / TIMED_OUT
```

1. 调用 `cancel()` 表示发出停止请求，返回 true 不代表底层工作已经停止。
2. `TaskHandle.result` 在执行器真正结束后才完成；不可中断执行器一直不结束时，任务保持 STOP_REQUESTED 且占用槽位，不自动启动下一个任务制造重叠计算。
3. 回调执行器新增第三个 `CancellationSignal` 参数；现有两个参数的回调仍可使用，但不会自动具备中途取消能力。
4. 执行器必须等待自己启动的子任务全部结束，再结束 Promise。不得启动脱离管理的后台计算后提前返回。
5. 首个停止原因保留。超时后迟到的成功结果不会发布；取消后再次取消返回 false。
6. 预热期间取消，等待预热结束后不再启动推理。
7. `timeoutMs` 表示累计活动执行时间上限（包含预热，不含排队/暂停）。语义任务的 `deadlineMs` / `freshnessMs` 从提交时刻计时，覆盖排队与暂停；到期请求停止，仍需等待执行器真正退出。
8. `shutdown()` 同样等待正在执行的工作结束；不强杀手机系统进程。

## 日志与指标

`stopRequestedAt` 是请求停止的时间，最终日志 `finishedAt` 是执行器完成并确认任务终结的时间。两者间隔可以反映停止响应开销。

`averageLatencyMs` 和 `p95LatencyMs` 现在按完成任务的 `totalDurationMs` 计算，包含排队与执行；仍可通过各任务的 `executionDurationMs` 查看纯执行时间。统计窗口包含成功、失败、取消与超时终态，实验时应按状态分组解释。

## 尚未完成

语义任务已支持检查点重新排队及排队截止时间，应用后台索引已接入分块协议。逐字段真实状态 TTL 已覆盖公共状态控制器；manifest 路径额外保留原方案的 10 秒观测保护，不被电池/温度 30 秒 TTL 放宽。撤销无实际预算的 THROTTLE 策略输出：可暂停的后台受保护时暂停，不可暂停的旧后台任务拒绝准入。本版不提供速率预算型限流。手机性能与能耗验证仍待完成。块间配置调整不等于不可抢占推理的中途降档，也不代表内核抢占或手机硬件全局控制。

2026-09-21 整合说明：语义 SDK 与旧回调入口共用停止协议。取消、超时、结果过期、设备保护与关闭时，运行中的任务先进入 `STOP_REQUESTED`；重复请求不覆盖首次原因。排队中未开始的任务可直接终结。测试入口必须同时包含安全回归和语义契约用例。

受约束路径的取消确认看门狗与该状态兼容：等待超过 2 秒只记录未确认并熔断配置，不释放执行槽。全局暂停不阻止队列保护重评估；排队配置不受支持时先尝试契约内合法 fallback，仍不可执行则失败。最新合并证据见 [第二轮整合验收](testing/07-resource-experiment-integration.md)。
