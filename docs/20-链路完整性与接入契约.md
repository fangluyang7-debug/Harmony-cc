# 链路完整性与接入契约

## 结论

`harmony-agent` 的手机 Scheduler → measured cloud route → API Runtime → task graph → executor → business session/candidate/memory 链路已闭合。`cixin-agent` 已具备独立调度、取消确认、遥测和节点执行链，并新增 `HttpHarmonyShoppingTransport` 作为可选桥接；只有在管理员配置并探测通过后才应把 Cixin 节点加入正式购物执行器。

模型接入使用 `core/runtime/model-provider.port.ts`，上传使用 `core/runtime/upload-channel.port.ts`。两者均不把密钥、模型 SDK、COS URL 或业务正文放入 TaskGraph；接入实现完成后仍由调度器先做能力与质量门槛判断。

## 与 original-app 对齐

正式鸿蒙 App 已覆盖原应用的文字搜索、图片检索、候选列表/详情、价格与库存视图、筛选/主体/画像调整、候选刷新、收藏/历史、反馈校准、账号登录和监控设置。长期记忆由服务端 `users/me/profile`、`profile/context`、记忆提案确认/拒绝接口提供，回合处理会生成提案并把已确认偏好注入搜索过滤；端侧鞋码偏好保留为设备级快速偏好。演示 Web 入口是联调工具，不应被当作完整购物客户端，正式演示以 `apps/harmony` 原生入口为准。

## 已验证与边界

- Runtime 用户 JWT、运行归属、取消/遥测隔离和维护接口均有 HTTP 测试。
- 任务级 `minimumQuality` 与工具门槛合并后参与候选过滤；冷启动没有绕过实测路由或质量门槛。
- 超时/取消保留活动执行直到 settled；不响应停止的执行器进入 `stop_unconfirmed`。
- readiness 分能力检查数据库、COS、chat、vision、embedding 及 visual/multimodal 索引覆盖；空库、错误维度、非法向量会阻断对应能力。
- 上传通道已存在于 `POST /api/v1/assets/images`，要求登录并绑定 `ownerUserId`；手机只上传到 API，COS 凭据只在服务端。

仍需真实模型凭据、商品向量数据、Zeabur 部署和签名真机操作才能宣称线上购物成功；代码测试通过不替代这些外部验收。
