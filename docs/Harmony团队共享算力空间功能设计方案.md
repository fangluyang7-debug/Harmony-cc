# Harmony 团队共享算力空间功能设计方案

**产品愿景：像建群一样连接设备，让团队中的每个人都能便捷地使用集体算力。**

Harmony 将分散在团队成员手中的手机、普通电脑、GPU 工作站等设备组织为一个共享资源空间。成员通过邀请加入，按意愿贡献设备资源，按权限使用团队算力；系统根据任务需求、设备状态和团队规则协调分配，并通过统一控制台展示整个过程。

最终形成完整的使用闭环：**创建空间 → 邀请成员 → 接入设备 → 提交任务 → 协同执行 → 获取结果 → 查看贡献与用量。**

## 一、创建团队算力空间

任何成员都可以创建一个独立的算力空间，设置名称、介绍和加入规则，并成为空间负责人。

负责人可以通过邀请链接、二维码或邀请码邀请其他成员。邀请支持有效期、使用次数限制和随时撤销；空间可以选择直接加入或审批加入。

成员与设备分开管理：一个成员可以接入多台设备，也可以仅使用团队资源。设备接入后，以卡片形式出现在空间中，显示名称、所有者、可提供的能力和当前状态。

**期望效果：团队建立共享资源环境的过程，像创建群聊、邀请成员一样清晰直观。**

## 二、设备按意愿共享，随时加入和退出

设备主人决定是否贡献资源，以及贡献多少、什么时候贡献、允许执行哪些任务。

每台设备可以设置：

| 设置项 | 功能 |
|---|---|
| 共享范围 | 面向全体成员、指定成员或指定任务开放 |
| 可用时间 | 持续共享、仅空闲时共享、按时间段共享 |
| 资源额度 | 设置允许共享的计算资源、内存和存储额度 |
| 使用保护 | 优先保障设备主人的正常使用 |
| 手机保护 | 设置充电、电量、温度和网络条件 |
| 暂停与退出 | 随时暂停接收新任务，或退出当前资源空间 |

设备状态统一呈现为“可用、执行中、仅供本人使用、暂停共享、离线”等，避免将已连接但不可使用的设备计入可用资源。

当设备主人重新使用电脑，或手机不再满足共享条件时，系统相应减少分配或停止新增任务，并处理受影响的工作。

**期望效果：资源共享可控、可撤回，设备主人始终知道自己的设备正在为谁做什么。**

## 三、提交任务，即可使用团队算力

成员从手机或电脑进入空间，选择任务类型、添加输入内容，并设置期望完成时间或紧急程度。

任务提供两种使用方式：

- **自动分配：**成员只需说明要完成什么，由系统选择合适的资源。
- **指定分配：**成员在权限范围内指定设备、资源类型或执行时间。

提交前，系统展示预计等待时间、预计完成时间，以及任务需要使用的设备和数据范围。无法满足要求时，明确说明原因，并提供可选调整方式。

任务提交后，成员可以查看进度、取消任务、接收完成通知和获取结果。对于包含多个步骤的任务，结果统一汇总，成员不需要分别到各台设备寻找文件。

**期望效果：只有手机的成员，也能从手机发起需要团队 GPU 完成的工作，并直接获得结果。**

## 四、自动协调设备，让合适的资源承担合适的工作

系统根据任务需要，综合考虑设备能力、当前负载、排队情况、数据位置、可用时间和团队规则进行分配。

能够独立处理的批量任务，可分配给多台设备同时执行；包含不同处理步骤的任务，可由不同类型的设备接力完成。

例如，一批图片可以由普通电脑进行整理和预处理，由 GPU 设备完成视觉分析，再统一汇总输出。

自动协调遵循以下原则：

- **能力匹配：**任务只分配给具备相应能力的设备。
- **整体效率：**综合考虑等待、传输和处理时间。
- **主人优先：**共享任务服从设备主人设置的使用边界。
- **规则优先：**遵守团队权限、预约和资源保障要求。
- **持续调整：**设备状态变化时，重新安排尚未完成的工作。

系统应允许设备保持空闲。当继续分配无法带来收益，或会明显影响设备主人时，不为提高利用率而强行派发任务。

**期望效果：成员无需反复询问“谁的电脑空闲、谁有 GPU”，系统能够主动组织协作。**

## 五、负责人可以制定资源分配规则

空间负责人能够为成员和任务设置权限、优先级、使用额度及预约安排。

| 管理能力 | 期望效果 |
|---|---|
| 成员角色 | 区分负责人、管理员、普通成员和观察者 |
| 资源访问权限 | 限定成员能够使用哪些设备和任务能力 |
| 优先级 | 紧急任务或指定成员优先获得资源 |
| 基本保障 | 为成员保留一定的资源使用机会 |
| 闲置借用 | 保障对象暂时不用时，其他成员可借用资源 |
| 时间预约 | 为演示、实验或批量任务预约指定时段 |
| 使用额度 | 设置成员或任务的使用上限 |
| 公平分配 | 避免少数成员长期占用全部资源 |

例如，负责人设置“GPU 优先保障成员 B”。B 没有任务时，其他成员可以使用；B 提交任务后，系统优先安排 B，并清楚展示其他任务的等待或让出安排。

负责人可以查看受影响的任务，再调整规则。团队规则始终在设备主人授权的共享范围内生效。

**期望效果：自动调度与人工管理相互配合，既方便日常共享，也能保障关键任务。**

## 六、统一控制台，让协同过程看得见、解释得清

控制台提供团队总览、设备视图、任务视图和分配记录。

**团队总览**展示在线设备、当前可用资源、运行与排队任务、已完成任务，以及需要处理的异常。

**设备视图**展示每台设备的所有者、共享范围、资源状态、正在执行的任务和近期贡献。

**任务视图**展示任务由谁提交、当前进度、各步骤在哪台设备执行、预计完成时间和结果位置。跨设备协作以流程形式呈现，让成员能够看见任务在设备之间的分工与衔接。

**分配记录**使用易懂的语言解释系统决策，例如：

> “选择 A 的电脑：当前空闲，预计完成时间最短。”  
> “任务正在等待：GPU 优先保障 B 的预约任务。”  
> “暂停向该手机分配：已达到设备主人设置的电量下限。”  
> “原设备离线：剩余工作已重新安排。”

不同角色看到与其权限相符的信息。团队成员能够了解资源状态，但不会因此自动获得其他成员的任务内容和结果。

**期望效果：控制台既是资源仪表盘，也是团队理解和干预调度过程的入口。**

## 七、设备变化时，任务仍然有清晰去向

设备离线、暂停共享或任务执行失败时，系统主动识别受影响的任务，并向提交者说明状态。

- 有其他合适资源时，重新安排可继续或可重做的工作。
- 能保留进度的任务，尽量从已有进度继续。
- 需要重新执行的部分，明确展示重做范围。
- 暂时没有合适资源时，进入等待状态并说明原因。
- 无法继续时，保留已有结果并提示需要采取的操作。

成员无需持续盯着控制台，也不会面对长时间没有解释的进度停滞。

同时，空间保留任务记录、资源使用记录和管理操作记录，支持查询“谁在什么时候使用了哪些资源、完成了什么工作”。

**期望效果：设备可以灵活进出，任务状态始终明确，执行结果可追溯。**

## 八、让贡献与收益可感知

空间展示成员贡献与资源使用情况，包括共享时长、完成任务数、CPU 与 GPU 使用时长等，并分别呈现不同类型资源，避免将所有贡献简单折算成一个不透明分数。

成员可以看到：

- 自己的设备为团队完成了哪些任务；
- 自己使用了哪些团队资源；
- 哪些设备经常繁忙，哪些资源长期闲置；
- 当前规则是否造成明显的等待不均衡。

这些信息帮助负责人调整共享时段、资源保障和任务安排，也让贡献资源的成员获得清晰反馈。

**期望效果：团队不仅能够共享资源，也能够理解共享带来的实际收益。**

## 九、国赛决赛路演的目标演示

路演围绕一个完整故事展开：**一个资源配置不同的小团队，共同完成一项原本需要人工协调的批量视觉处理任务。**

| 环节 | 现场操作 | 观众应看到的效果 |
|---|---|---|
| 1．创建空间 | 负责人创建 Harmony 团队空间，展示邀请二维码 | 算力空间像群聊一样建立 |
| 2．设备加入 | 成员加入，并接入手机、CPU 电脑和 GPU 电脑 | 控制台出现不同设备及其能力 |
| 3．设定共享 | 设备主人设置共享条件，负责人设置 GPU 优先保障 B | 个人控制权与团队规则同时成立 |
| 4．手机提交 | 一名成员从手机提交批量图片任务 | 手机能够发起超出自身算力的工作 |
| 5．自动协同 | 系统分配预处理、视觉分析等工作 | 多台设备承担不同步骤，进度实时变化 |
| 6．优先级生效 | B 提交紧急任务 | GPU 分配发生调整，控制台解释原因 |
| 7．设备退出 | 一台 CPU 电脑暂停共享 | 系统识别变化，重新安排受影响的工作 |
| 8．结果交付 | 任务完成，手机收到通知并打开结果 | 跨设备执行形成统一交付 |
| 9．回看贡献 | 展示任务分工、资源用量和成员贡献 | 共享过程透明，团队收益可见 |

演示结束时，观众应能明确理解三件事：

1. **接入简单：**通过邀请，把分散的设备组织成团队资源空间。
2. **协同有效：**成员提交任务后，系统按能力、状态和规则协调设备。
3. **共享可控：**设备主人掌握共享边界，负责人能够管理优先级，成员能够看懂任务去向。

路演中的性能收益以实际测量为准；如展示对比，应使用相同任务和一致条件，比较完成时间、等待时间及人工操作步骤。
