## 联调准备与操作

1. 在协作者自己的集成分支合入本分支，再构建协调器、PC 代理和前端 SDK。完整构建时先停止占用该构建目录 Prisma DLL 的协调器；本机曾遇到文件占用，不能把旧 dist 当作新源代码。
2. 按实现说明准备照片模型和运行器，Windows 代理构建需配置 `HARMONY_PHOTO_RUNTIME`。构建协调中心分发包、Windows 应用与鸿蒙安装包后再验收；源码推送不代表协作者旧安装包已经更新。
3. 鸿蒙先构建 scheduler HAR，再构建 `harmony-agent --har`。默认 API 22 保留；本机实测是显式 `HARMONY_BUILD_API=24` 的独立工程。协作者须使用自己的 SDK、设备签名；模型、SDK、签名、`.test` 账本均未推送。
4. 启动局域网协调中心，设备连接同一可互访 Wi-Fi。手机与 Windows 加入同一空间，确认照片能力通过实际资格验证；手机保持前台。
5. 手机进入调度盘 → AI 照片工作台，选择手机上的照片；本地调试也可用上述 USB 导入入口。一次选好后，两轮保留相同输入和预算，不重复导入而增加照片数量。
6. 先选择“只用发起设备计算”并开始，完成后选择“自动规划协作”再开始。大屏打开同一协调中心的 `/photo.html?space=<空间ID>&view=judge`，调度盘仍为 `/dispatch.html?space=<空间ID>`。
7. 每轮保留运行 ID、输入哈希、模型、预算、节点目标/回执、端到端耗时和成品。页面中“导出本轮证据”可查看实际分配；失败记录保留，不能当成成功对照。

这里的单机是“计算限定手机”的联网编排基线。任务素材不得提前塞入 Windows/GPU 执行器，模型和通用资格验证样本可以预装。旧本机 `127.0.0.1` 演练端口是临时入口，不是协作者部署地址；`SIMULATED` 本机演练不能替代真机结果。

## 实测结果与未完成项

同一 96×64 自然照片测试裁剪、Real-ESRGAN x4plus、180 秒预算：

| 组别 | 手机计算 | 手机 + Windows |
|---|---:|---:|
| 第一组 | 26.251 秒 | 23.038 秒 |
| 第二组 | 20.587 秒 | 24.880 秒 |

四轮均七个唯一执行节点、七份提交回执及完整交付。协作实际为手机分析、Windows 增强/合成；未实现手机与电脑增强分片同时执行。两种平台结果只有极少像素通道相差 1，完整证据已入库。

**尚未证明稳定加速。** 不把第一组较快的结果单独用作性能结论。Windows CPU 在当前样本上的两个增强节点甚至比手机更慢，且阶段控制/交付等待占比较大。任务初始成本预测也明显偏小，需要按实际图块尺寸、设备与阶段校准。

建议接续顺序：先完成分发包及手动接入全流程联调；再基于逐阶段追踪优化控制等待和尺寸相关成本估计；然后用较大真实照片进行重复对照，最后接入 NVIDIA 设备测试 GPU 资格、实际分配与提速。无需为了让两个设备都出现而安排无用计算或降低手机配额。鸿蒙电脑、NVIDIA、API 22 真机、较大图像的内存/温控及取消/断线恢复仍待验收。
