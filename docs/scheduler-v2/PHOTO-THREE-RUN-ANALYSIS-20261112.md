ready→最后推进包含输入准备及重复尝试，不全是纯调度空等；阻塞次数是协调中心准入检查失败次数，不等同于设备失败或重复执行。GPU 间隔来自同一设备时钟，可做区间相减，但包括加载、传输、发布、控制准入等，不等同于可全部消除的闲置时间，更不是显卡利用率百分比。

最新轮较前轮快 1.564 秒（11.60%），并非 GPU 计算合计下降：它反而增加了 0.373 秒。可见 GPU 计算窗口更紧凑、最终派发准备更短，且成功设备分工改变。具体各因素对墙钟收益的独立贡献不能由两个并发样本精确归因。最新轮 GPU 有一片 EXECUTE 856.2 ms，其余约 53.7–168.9 ms；startup/overhead 未拆分，不能断言峰值源于重复加载模型或热状态。

传输记录：前轮接收区间合计 722.2 ms、发送 665.1 ms；后轮接收 505.8 ms、发送 817.7 ms。这些区间会并发，也可能对应同一传输两端，不能相加当端到端网络耗时。单次接收最大分别 199、123 ms，没有单次长文件传输足以解释 9–10 秒等待的证据。下一步优先核对额度释放、画像/credit 更新、下一片派发之间的时序，再讨论网络优化。

## 首张结果与后续方向

电脑展示端收到首张结果：单机约 8.547 秒；两轮协同约 10.762、10.407 秒。协同完成全批更快，但首张结果出现更晚。展示接收时间含轻微上报传输开销，与源端计时略有差别。

优先建议：

1. 追踪 GPU 已结算回执→资源画像/credit 可用→下一 offer 的间隔，解决仍存在的 173/209 次准入竞争；不要直接删除原子额度检查。
2. 对快速 GPU 分块减少重复输入准备、逐片控制往返及等待，评估有界预取/排队，让计算连续；不能预先准备业务结果。
3. 规划不仅比较单片计算，还校正占用时长及发布/传输成本，避免低估下一片能开始的时间。
4. 保持整批吞吐的同时评估“优先完成一张、其余继续流水”的策略，改善评委长时间看不到首张成品的体验。
5. 后续增加同序三图重复轮次，并让单机展示记录带模型、预算和执行阶段元数据，得到更完整的公平对照证据。
