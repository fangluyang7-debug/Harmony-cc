# 图片 App 模式切换与接入就绪 R5（2026-11-12）

## 实测问题

用户要求五分钟路演内减少从本机处理切换到协作后的接入准备。基于当前 `codex/main-gpu-integration-20261112` 工作区继续修复，保留既有 R2/R3/R4 和 GPU 常驻模型，没有拉取或覆盖协作者新代码。

旧版真机仅点击连接、不提交任务，即复现页面 **51.8 秒**准备。会话 `desktop-172.20.10.6-FMT0BM` 的图片宿主 `261fec4d…` ledger epoch 3 重新执行 22 项照片参考检查，首末创建时间跨度 **21.728 秒**，实际执行累计 **3.547 秒**。跨度不含末例执行结束，也不是纯网络时延；总准备还包含首例之前的轮转及资格刷新。不能把差值全归为传输或模型加载。

## 修改

1. 同一进程切换模式保留代理。`PhotoSession.prepareLocal()` 改为 `NativeAgent.pauseForLocal()`：禁止新准入，等待已接收工作结算，释放额外配额，发布零可用贡献，保留控制连接、ledger 和身份。恢复使用原代理和真实资格，不重建 epoch、不重复启用性能配置。不同身份/重新授权仍通过 `retireHost()` 结算并关闭。退出进程、资格过期、模型/执行器/配置变化仍可能重新校准。
2. 校准队列快速跳过阻塞项。同一设备一次最多遍历一圈目标，遇到进行中的校准才让出，后台宿主的无关能力不再各消耗一秒轮询间隔。ACTIVE 每五秒复核，阻塞项按正常间隔复核，进行中的套件继续推进。同设备仍串行，完整检查不删减。
3. 保留校准唤醒信号。`EvaluationChanged` 到达忙碌宿主时设置待处理标记，结束后立即再领取，避免丢失事件后等待两秒心跳。本机模式不领取校准工作。
4. 修复参考任务让出资源导致的重连循环。真机接入时发现旧节点也为校准发送 `YieldNotice`，中心仅查业务 Attempt，返回 `YIELD_SCOPE`，可靠消息重发导致持续断连。新增 EvaluationDispatch 作用域校验，只接受本设备已领取的 RESTART 通知，标记取消请求；仍等待真实执行报告结算，不伪造质量或释放资源。重复通知可 ACK，错误设备/未知任务仍拒绝。

## 合并必须保留

- 本机照片仍仅在手机计算。保留连接不等于使用远端算力；本机模式不上传业务输入、不创建协作任务、不进行参考校准。
- 准备只执行公开参考用例，不读取、编码或预处理所选照片，无电脑预存原图/成品。
- 绿色就绪仍来自当前身份、模型与配置的有效资格，不使用固定延时标绿。源端就绪不代表所有远端/GPU 就绪。
- 准备与业务计时独立；开始后的全部传输、调度、计算、接收仍完整计时。
- 代理暂停/恢复、PhotoSession 身份切换、校准推进及 YieldNotice 修复须一起保留，不能只改按钮或缓存一个布尔就绪值。
