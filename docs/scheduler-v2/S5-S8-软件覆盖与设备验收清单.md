# S5—S8 软件覆盖与设备验收清单

更新于 2026-11-04，分支 `codex/scheduler-v2-foundation`。本文反映本机工作树。复现从仓库根目录安装锁定依赖后开始，Windows PowerShell 可使用 `npm.cmd`。

## 可演示的链路

| 切片 | 当前入口和行为 | 已有软件证据 |
| --- | --- | --- |
| S5 多设备任务与数据交付 | SDK 提交 DAG；源端产生输入，工作节点执行，固定服务消费已提交产物。直连失败可在原期限内转经协调器。 | 双代理真实控制连接、进程、TLS 和字节校验；断开 B→C 后保留两端到中继的连接，检查两跳交付、剩余预算、每个逻辑节点的尝试数。见 STATUS §78、§80。 |
| S6 额度、调度与恢复 | 协调器按团队和应用分配就绪任务；设备执行前原子检查共享资源。已准入任务要实际结算。队列超限可凭持久化未启动证明改派，PURE 交互任务可在有足够预算和可读输入时启动备份。 | 双 App 在已确认双槽容量内并行；同池干扰反例、让出、断线、显式取消、单任务/DAG 改派以及竞争结果的独立结算。五轮等待数字仅对应 §79 的测试负载。 |
| S7 图像任务和第二个 App | SoleAI 选图后可以调用业务服务编码，也可以经 SDK 使用已准入的团队执行器，再用同一索引检索。索引器提供批量编码、事务写入、本地以图查询。 | 业务 HTTP、SDK、模拟 CPU/CUDA 后端及模型拒绝分支，索引回滚和版本隔离。鸿蒙 CPU 适配器校验转换制品与输入张量。SoleAI 和索引器均有 API 24 HAP 编译证据。详见 §70—§74、§77—§78。 |
| S8 展示、反馈和报告 | 来源 App 邀请同组展示端；接收者同意并实际看到某一版本后点击确认。撤销、退出或过期后关闭投递。执行目标性能持续漂移时撤下并重新校准。 | API 24 模拟器完成两版展示、人工动作模拟、撤销清屏和退出，代理协议一致性 8/8。PC 运行轨迹与分桶再校准回归见 §75—§77。 |

## 本机复现

1. `npm run acceptance:report` 构建依赖、运行本机软件用例，并生成 `artifacts/acceptance/<日期>/SUMMARY.md` 与 AC1—AC8 明细。它记录测试环境、用例、源码摘要及单项待设备工作。
2. 中继故障注入在 `services/coordinator` 下设置 `HARMONY_TEST_BLOCK_BC=1` 后运行 `node --test test/workflow.test.cjs`。单独运行普通场景前清除该变量。
3. 图像软件边界可运行 `node --test services/api-server/test/image-search-v2.test.cjs tests/sdk/native-image-encoder.test.cjs tests/sdk/indexer-storage.test.cjs`。业务服务测试需先执行 `npm --prefix services/api-server run build`。模型打包格式见 [X6 实验记录](../experiments/X6-跨端图像模型.md)。
4. 展示模拟器使用专用回环实例，配置 `HDC_TARGET`、`HDC_PATH`、`HARMONY_AGENT_HAP` 后运行 `node tests/sdk/display-emulator.cjs`。源端通过业务接口发布，检查接收端布局元素和点击后的协议确认。
5. 设置 `HARMONY_IMAGE_TEAM_TEST=1` 后运行 `node --test services/api-server/test/image-search-v2.test.cjs`，同一次运行可遍历服务收图、来源宿主编码和远端编码三条路径。两台逻辑设备在本机使用已配对的 PC 代理；实际 SDK、协调器、资格评测、交付和业务 HTTP 均启用，图片引擎与 GPU 读数为替身。检查输出候选、来源本地零传输、远端实际派发设备和模型身份。完成后清除该变量。

## 待设备及环境验收

| 环境 | 应当取得的证据 |
| --- | --- |
| 正式 API 22 环境 | 从同一工作树重新构建 HAR、SoleAI、索引器和 agent，记录制品摘要，跑两 App 与代理一致性。当前 API 24 编译与模拟器数据单列。 |
| PC-B CUDA 与真实 X6 模型、索引 | 冻结独立评测集、质量门槛、预处理和权重摘要；对照真实设备、后端、显存、冷/热耗时与 CPU 回退。测两种检索接口的相同输入、同一索引版本及结果质量。 |
| 手机、PC 和真实局域网 | 从 UI 选图完成手机编码、PC 编码回传、业务收图三条路径；测实际传输大小、路径、期限、尾延迟和质量。断开指定直连后验证两跳交付和无重复业务计算。 |
| 同机双 App | 记录 ODID 关联、前后台切换、额度竞争和失联重连。批量索引时记录交互等待、可用容量和未结算占用；前提不成立时保留阻塞原因。 |
| 展示设备及现场网络 | 从检索结果发起邀请，核对接收端实际屏幕、版本覆盖和撤销。记录温度、电量、所有者活动以及控制连接抖动，校准失联与性能漂移阈值。 |

协调器、业务检索服务和本机编码子进程是三个独立角色。路演引用耗时须注明测量边界。真实模型质量、物理链路和功耗仍需以上设备实验提供数据；关键路径缺少跨设备因果证据时，调度盘保留 UNKNOWN。
