# Harmony 只读调度盘

正式页面源码为 [`apps/team-space-web/dispatch.html`](../../apps/team-space-web/dispatch.html)，样式与数据逻辑分别在同目录的 `dispatch.css`、`dispatch.js`、`dispatch-view.mjs`；`dispatch-charts.mjs` 处理只读图表比例和同域相对时间轴，`dispatch-layout.js` 负责视图导航、展示模式、拓扑布线及刷新时的交互状态保留。协调者访问路径为 **`/dispatch.html?space=<空间 ID>`**，也可登录后在页面中选择空间。

原 [`调度盘/code.html`](../../调度盘/code.html) 已改为入口说明，移除旧产品名称与固定硬件数字；[`调度盘/DESIGN.md`](../../调度盘/DESIGN.md) 保留为早期视觉参考。当前页面按用户新要求采用雾白内容区、深海军蓝侧栏/拓扑画布、蓝色重点与青绿/琥珀状态色。界面字体为本地 Noto Sans SC 可变字体子集，正文及小字统一无衬线字体，数值采用等宽数字特性。页面不依赖外部 CDN、在线字体或图表库。

## 启动与入口

在仓库根目录安装和构建现有协调者及 PC 代理：

```powershell
npm ci
npm run conformance:build
```

按 [局域网协调者说明](LOCAL-COORDINATOR-20261031.md) 启动。以下 IP 必须替换成协调者本机网卡的实际 IPv4：

```powershell
npm run coordinator:lan -- 192.168.1.20 7443
```

该启动器已经将 `COORDINATOR_WEB_DIR` 设置为 `apps/team-space-web`，并执行数据库迁移。手动启动现有协调者时，将该变量指向此目录的绝对路径即可，不需要另建网页服务器。

1. 通过已有控制台登录，创建或加入空间。
2. 进入空间，在右上方点击“只读调度盘”；VIEWER 也可进入。
3. 在调度盘中选择任务，查看持久化决策和有权读取的阶段追踪。

直接以 `file://` 打开 HTML 不能读取已认证的协调者数据。调度盘没有登录、创建成员或提交任务的新流程，这些操作继续使用现有控制台与 SDK。它不自动创建示例设备、任务或“演示指标”。

## 路演展示方式

页面按讲解顺序分成五个视图，同一个协调者会话与实时快照贯穿所有视图：

1. **运行总览**（`#overview`）：设备数、有效画像设备数、执行目标、执行记录，以及协同拓扑、网络等级和最近三条执行记录。点击最近任务即可进入该任务的证据页。
2. **设备资源**（`#resources`）：每个设备的宿主画像、CPU/内存资源池、执行目标、采集来源及额度结算。额度与采集依据可展开查看，实时刷新保持展开状态。
3. **任务追踪**（`#tasks`）：左侧选择任务并读取持久化决策、规划估计；右侧展示各时钟域的阶段实测区间。常见任务与阶段采用中文标签，同时保留能力编码和阶段编码。
4. **网络链路**（`#network`）：方向探测与直传授权记录；没有证据时明确显示空状态。
5. **异常记录**（`#recovery`）：已记录的拒绝、让出、失败和恢复能力边界。

顶部提供“大字展示”和全屏按钮。大字模式提高字号，继续保留只读、数据域、历史快照和测量不完整提示；它不改变数据和调度行为。全屏可用 Esc 退出；浏览器拒绝或不支持时显示提示，仍可正常使用页面。视图可通过上述地址片段直接打开，支持浏览器前进/后退；窄屏将侧栏改为顶部五项导航。字体与图形均在本地渲染，不依赖联网下载。

推荐讲解顺序：总览说明协作拓扑 → 设备资源说明实际贡献 → 点击执行记录说明设备选择与阶段耗时 → 按需展开网络及异常证据。展示密度随实际设备数、任务数和窗口尺寸变化；需要时可以滚动查看全部记录，页面没有自动轮播或自动切换选中任务。

### 图形的含义

- **协同拓扑**：中心为协调者，终端只来自当前快照；SVG 虚线按实际节点位置布线，仅表示画像关联。点击终端进入对应资源卡片。未上报、未采集和过期画像有不同文字说明，不绘制虚构手机/GPU，也没有代表“正在传包”的装饰动画。
- **资源环形图**：`任务占用 / 准入上限`，不代表整机 CPU 利用率。未知或上限为 0 时使用断续空环与 UNKNOWN；真实零占用显示 0%；超出上限时保留超过 100% 的数字、标明超额，圆环只封顶绘制一圈。
- **网络分布**：L0—L3 色条表示快照内各等级的宿主数量，旁边列出精确计数；不是对网络健康度打分，也不把单个宿主等级推广为整个空间等级。
- **规划成本**：基线与所选估计使用同一比例尺；缺失值保持 UNKNOWN 和斜纹轨道，真实 0 保留。估计不冒充实测收益。
- **阶段时间线**：每个 `clockDomainId` 独立从该域已记录的最早跨度开始计时，横轴终点为该域最后跨度的相对结束点。条形位置和长度分别对应同域相对开始时间与实测时长；允许显示真实间隔/重叠，零时长用细线标记。不同域不对齐、不合计，该域横轴跨度不称为完整端到端耗时。

字体文件与许可在 [`fonts/`](../../apps/team-space-web/fonts/README.md)。新增中文界面文案时可运行 [`build-dashboard-font.py`](../../scripts/build-dashboard-font.py) 更新子集；任意设备名称中未包含的字符仍回退到系统中文字体。

## 数据来自哪里

| 面板 | 只读数据来源与展示范围 |
| --- | --- |
| 设备与执行目标 | 当前空间的 `SpaceDevice`、`DeviceDirectory.profiles()` 和能力资格记录；包括未在网页登记、但已有正式画像的 SDK 宿主；同一物理设备按 holder 分别显示 |
| 资源占用与排空 | 画像中的各资源池、当前空间的额度 grant / ack / reserved；协同槽位与任务占用不冒充整机利用率，多个 holder 的物理总量不重复相加 |
| 网络状态 | 既有 `DirectTransfers.dashboard()` 的每宿主 L0–L3 分级、成对探测与 TTL，以及方向开销/带宽拟合；没有证据时显示 UNKNOWN，不能从拓扑连线推定直连成功 |
| 直传记录 | 当前空间 `TransferAuthorization` 的状态、方向、字节数和端点设备；COMPLETED 表示端点已确认；不返回签名、proof 或凭据 |
| 调度决策 | `CpuJob` 中已保存的 plan、快照/策略版本、目标、原因、基线与所选成本、候选拒绝码；全部成本明确标为规划估计；页面不调用规划器重新排序 |
| 任务追踪 | 复用 `TraceService.read()` 的跨度和分析结果；沿用原有 principal reader 范围，非授权任务返回 403；同域按 `startMono` 排序，不比较跨设备绝对时间 |
| 异常与恢复 | 当前记录窗口的拒绝、失败、未知状态、YieldNotice 与资源结算状态；备份执行、故障改派暂按 S6“尚未接入”显示 |

每份快照带 `domain` 和 `updatedAt`。SIMULATED 数据域在顶部明确提示。未知、无效、未来或过期的 sample 不显示为 0；真实的 0 会保留。温度单位为 `level` 时显示“级”，不会转换成摄氏度。样本的来源在资源池或指标提示中保留。

当前只持久化了基线、所选方案与拒绝信息，没有完整的全候选成本表，因此缺少的备选成本继续显示 UNKNOWN。来源 SDK 在原始提交前启动同域单调计时、完整读取并校验结果后确认领取时，接口可返回 `coverage.sourceSdkRoot=true` 和实测 `sourceDurationMs`，页面显示“SDK 端到端”。恢复任务没有原始起点、测量端口不可用或确认尚未到达时，来源耗时仍为 UNKNOWN；不从执行阶段之和推算。

追踪查询已关联来源根、已提交前置、规划/派发、校验收货和同进程副本转交。时间线下方“因果依赖”可展开查看边及其证据原因，并展示已测因果链；该局部数值未计入跨端未知间隙。传输工作量按同一授权的完整发送区间计一次，接收端就绪时刻独立保留，不能因等待 HTTP 响应而推迟已经开始的下游。

完整计量由 `analysis.status`、`causality` 和 `coverage` 判断。当前跨端实际链路仍有未知时钟间隙、部分传输边界和旧中继数据阶段，完整关键路径与未解释耗时继续为 UNKNOWN。各时钟域的阶段实测区间独立展示，范围不足时保留说明。

“分段估计与实测”列出同一规划快照/目标对应的 EXECUTE、QUEUE、PUBLISH 估计、实测和有符号误差。正数表示实测更长，负数表示实测更短；按段查看，不跨时钟相加为收益。历史任务没有对应估计时不补造数字；LOAD 与冷启动的完整拆分仍待后续。

## 接口与刷新

| 接口 | 行为 |
| --- | --- |
| `GET /v2/spaces/:spaceId/telemetry` | 返回授权空间的只读投影，最多显示最近 100 条执行记录；不返回输入、结果内容、原始 offer 参数或传输凭据 |
| `GET /v2/spaces/:spaceId/telemetry/traces/:jobId` | 取得该执行记录的授权追踪；无跨度时返回等待证据，权限不足返回 403 |
| `GET /v2/spaces/:spaceId/events` | 复用已有 SSE 失效提示；收到 changed 后重新读取快照 |

认证使用已有 HttpOnly 会话 cookie 和空间成员检查；接口发送 `Cache-Control: no-store`。没有数据写入、App 自动注册、额度签发、规划或派发操作。没有新增提交按钮。

除了 SSE，前台每 15 秒做一次快照校对以刷新 TTL、追踪晚到区间与遗漏事件；这是显示层校对，不是任务领取或派发轮询。重新进入页面或切换空间时重新读取授权快照。事件断开、快照失败会明确提示；读取失败后保留的内容标为历史快照，401/403 会清除当前数据。

实现入口：[`telemetry-view.ts`](../../services/coordinator/src/telemetry-view.ts) 只读投影，由 `spaces.ts` 的已有会话边界接入，`app.ts` 完成依赖装配；没有改变 PlanningService、代理执行或额度续租逻辑。

## 计划测试拓扑

下面是后续搭建建议，**不是已连接设备清单或验收结果**：

| 设备 | 分工 | 准备事项 |
| --- | --- | --- |
| PC-A | 局域网协调者与浏览器调度盘 | Node.js 22、npm、OpenSSL、稳定局域网地址；不要求独立显卡。未启动代理并上报画像时，不自动算作执行资源 |
| PC-B | 计算终端；显卡放在此机 | 运行正式配对的 PC 代理，贡献上限由所有者设置；GPU 目标/指标只有实际采集、注册并满足相应条件后显示，不能因机器装有显卡就补造数值 |
| 手机 / 平板 | 后续 SDK 来源与执行终端 | 画像未到位显示 UNKNOWN；真机待验，模拟器相关测试继续遵守 STATUS 中的暂停安排 |

当前网页不要求 PC-A 安装 CUDA。GPU 执行能力和真实性验收仍按相应 S7 工作包进行，不能由调度盘替代。两台 PC 的直连、中转和网络退化须由 S5 的真实探测及传输记录验证。

## 在途画像与等待估计

设备资源卡的「在途任务与资源等待」读取宿主最新画像。排队行显示申请量、等待原因与排队时长，已经准入的行显示所占资源池。已运行时长从本进程开始计算时计时，到账本确认结算为止，包含结果发布。相同输入内容、配置与传输路径有近期成功样本时可以显示预计剩余时间。超过历史用时且仍未结算、缺少样本、取消中或画像过期时显示 UNKNOWN。先更新协调者，再更新宿主。新协调者接受旧画像，旧画像未携带任务列表时显示 UNKNOWN。

调度决策中的「规划等待明细」按节点展示设备侧策略等待，以及同一任务图的其他分支占用资源产生的等待。所列毫秒均来自对应决策快照。实际等待请在任务时间线中展开「排队与资源结算观测」核对。
