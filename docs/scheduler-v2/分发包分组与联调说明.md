# Harmony 调度系统分发包分组与联调说明

发布按协调中心、设备调度件、业务应用三种职责分组。设备调度件按平台分别交付，当前共有四个包。后续代码、运行依赖、安装格式和支持平台可以更新，各包的职责和接入顺序保持一致。

## 固定分组

| 分发目录 | 安装设备 | 职责 |
| --- | --- | --- |
| `01-Coordinator-Windows-x64` | 作为协调中心的 Windows 笔记本 | 启停协调服务，管理空间和设备邀请，调度任务，提供调度盘。联调期间保持运行。 |
| `02-Device-Agent-Windows-x64` | Windows x64 执行设备，例如显卡机 | 导入邀请并配对，通过开关上线，报告资源与执行能力，接收并执行任务。 |
| `03-Device-Agent-HarmonyOS` | 需要接入的鸿蒙设备 | 搜索中心、扫码配对、管理本机设备身份，办理业务应用的接入授权。 |
| `04-SoleAI-HarmonyOS` | 演示购物业务的鸿蒙手机 | 通过「使用协同调度」开关申请独立应用身份，自动登记内置工作流，并在对应业务操作中提交任务。 |

演示手机安装第 03 和 04 包。第 03 包让手机接入空间，第 04 包让 SoleAI 以应用身份使用调度系统。新增其他平台的执行设备时，为该平台单独交付设备调度件，沿用设备配对、资源上报和任务执行的职责。

## 真机签名

两份 HAP 是未签名构建，直接 `hdc install` 会报 `code:9568320 error: no signature file`。真机安装前按下面顺序生成调试签名。

1. 手机连上电脑，`hdc list targets` 能看到设备。打开对应工程（设备调度件为 `.test/s2-harmony-agent` 或 `apps/harmony-agent`，SoleAI 为 `apps/harmony`）。
2. DevEco Studio 中登录华为账号，进入 `File > Project Structure > Project > Signing Configs`，勾选 `Automatically generate signature`。DevEco 会为当前包名申请调试证书与 Profile，并把当前设备的 UDID 写进 Profile，材料保存在 `%USERPROFILE%\.ohos\config`。
3. 确认 `build-profile.json5` 里两处都在：`app.signingConfigs` 有 `default` 条目，且 `app.products[0]` 有 `"signingConfig": "default"`。只生成材料、漏掉 product 引用时，构建日志会打印 `No signingConfig found for product default`，产物仍只有 `entry-default-unsigned.hap`，部署就会回到 9568320。用仓库脚本构建时不需要手工补：`scripts/harmony-v2-app-build.cjs` 会沿用暂存工程里已有的签名配置并自动挂到 product 上，日志会打印 `signing config default kept from previous stage profile`。
4. 重新构建，产物目录出现 `entry-default-signed.hap` 后再部署。命令行构建需要设置 `DEVECO_SDK_HOME`，并把 DevEco 自带 JBR 加入 PATH，否则签名工具按 `java` 查找失败。

签名材料与本机账号、设备绑定，不进仓库。换机器或换手机后需要重新生成；已装过旧包时用 `hdc install -r` 覆盖安装。同一部手机的两份 HAP 要分别签名，Profile 的包名必须与应用一致。

改了 `AppScope/app.json5` 的 `bundleName` 之后有两件事要一起做：旧 Profile 立即失效，必须在 DevEco 里重新生成；IDE 的签名向导只写入 `signingConfigs`，不会给 `products[]` 补 `signingConfig` 引用，因此生成完还要跑一次 `npm run harmony:v2:soleai`（或对应的 `harmony:v2:agent`），由脚本补上引用并产出签名包。直接点 IDE 的 Run 会重新得到未签名包并报 9568320。

## 队友联调步骤

1. **启动中心。** 笔记本打开第 01 包，选择其他设备能访问的局域网 IPv4，默认 TCP 端口 `7443`。中心就绪后创建空间，打开调度盘。发现使用 UDP `7444`。发现失败时仍可用邀请配对，前提是设备能访问中心的 HTTPS 地址。
2. **测试 Windows 接入和 CPU 任务。** 中心为显卡机生成一次性邀请。显卡机打开第 02 包，导入邀请 JSON，完成配对后开启调度件。确认调度盘上设备在线、CPU 能力就绪，再提交基础任务，查看实际执行设备和完成回执。开启后会自动采集 CPU 和内存资源。
3. **测试手机接入和 App 授权。** 安装签名后的第 03 和 04 包。为手机生成单独邀请，在设备调度件中扫码。打开 SoleAI 的「使用协同调度」并确认首次授权，随后在调度盘核对应用和工作流已登记。选图触发图片预处理，在任务详情核对执行目标和结果。
4. **按需测试 CUDA。** 显卡机先准备 NVIDIA 驱动、支持 CUDA 的 Python/PyTorch 环境、模型和图像编码评测套件。在启动器选择 `CUDA`，填写 Python 和套件路径。协调中心配置同一可信评测套件。调度件在 CUDA 执行环境启用后自动探测并上报 GPU 和显存。待 CUDA 能力就绪，在 SoleAI 的独立图像搜索入口触发图像编码，核对任务的实际执行设备为显卡机、后端为 `CUDA`，并保存完成回执。

每次测试记录构建提交、设备与系统版本、任务 ID、实际执行设备和后端。失败时附调度盘状态及错误码。设备在线、能力就绪和任务完成是三个独立检查点。本次已用独立 Windows 包验证中心启动、设备配对和 CPU 任务执行；手机真机扫码与授权、真实 CUDA 执行留待现场联调。
