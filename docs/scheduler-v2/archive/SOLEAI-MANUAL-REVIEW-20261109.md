# SoleAI 手机＋电脑并行：手动演示操作单

> 已被用户最新需求取代，仅存档。专用复核入口、手动选择目标、跳到 Harmony 前台计算均不再作为正式演示。当前操作说明见上级目录 SOLEAI-MANUAL-DEMO.md 与 STATUS §105。

本轮验收基准是**手机单机 vs 手机＋电脑协同**，不要求协同比 Windows 单机更快。双机必须有手机和电脑各自执行的真实分片，结果相同，并在计算阶段并行。不能把“手机提交、电脑全部执行”说成两端并行计算。

## 已准备的内容与验证范围

- SoleAI 新入口：“我的 → 购物图像复核 · 手机 / 双机对照”。
- 独立调度件新入口：`VisualReviewAbility`，前台承接图片获取、应用授权、SDK 提交、手机计算、结果合并，完成后回传 SoleAI。
- 两种模式共用相同原图、归一化、分片、CPU 算法和每任务 30 秒预算；每轮重新准备、上传任务输入，没有在计时前将图片/特征放入其他执行设备。
- 手机单机指**计算全部在手机**，仍使用同一局域网协调中心和 SDK；不是断开协调中心的离线原生函数基准。公共商品检索/原图下载单列，两种模式从相同来源原图开始计时。
- 两台本机 CPU 宿主、真实商品输入、正式 SDK/协调器已跑通：20/20 任务成功、结果哈希一致、唯一 attempt/committed/结算通过；同一进程时钟域下观测到不同宿主的 EXECUTE 区间重叠。它是功能替身，不是手机性能实测。
- API 24 HAR、03 调度件和 04 SoleAI 已签名构建。**本轮未安装到充电中的设备，未验证新入口的跨 App 跳转、原生解码、真机并行和速度。**不能据此宣布新入口真机验收完成。API 22 仍未验证。

## 现在就可以在 Windows 手动彩排

如果当前彩排服务仍运行，打开聊天中给出的本地彩排链接。重启后可在仓库双击 `scripts/Start-SoleAI-Rehearsal.cmd`，等待校准完成后浏览器自动打开，通常需要一至三分钟；该工具依赖本仓库已有开发环境。

1. 在“购物需求”中输入“500元以内的运动鞋”，点击“获取商品图片”。等待显示真实商品 runId 和图片数量。
2. 点击“手机单机路径（本机替身）”，等待 `SUCCEEDED`。
3. **不要重新获取商品**，点击“双机并行路径（本机替身）”，等待 `SUCCEEDED`。
4. 检查第二组表格出现两个不同设备 ID，两种模式的完整结果 SHA-256 一样。
5. 本页两组耗时只是本机功能彩排，不作路演性能结论。彩排服务使用独立临时数据库和设备身份，不影响已有真实协作空间。

## 真机演示前，只需准备一次

1. 先给手机更新本轮补丁目录中的 **03 Harmony 调度件与 04 SoleAI 两个 HAP**；只更新其中一个会缺页面或入口。补丁目录为 `dist/调度系统补丁-20261109-SoleAI手动复核`，按其中说明安装。调试签名只覆盖已授权设备，不是任意新设备安装包。充电结束后再安装，本次尚未安装。
2. Windows 和手机连接同一可互访的 Wi-Fi。USB 仅用于安装/调试，正式业务走 Wi-Fi。鸿蒙电脑不参与本轮双机对照；后续可另外验证，避免同一场演示混入第三台执行端。
3. Windows 运行现有 `shopping-visual-final` 的 01 协调中心和 02 Harmony 应用；已运行则不要重复启动。01 双击 `Start.cmd`，在启动页选本机 WLAN 地址、启动协调中心；02 双击 `Start.cmd` 打开应用。
4. Windows Harmony 内创建或进入已有协作空间，开启本机共享。手机 Harmony 扫码加入同一空间，开启共享。若已经在同一空间，直接恢复连接，不必退出重建。
5. Windows 打开这个空间的“调度盘”，确认两台设备在线，图像能力 `image.visual-match.v1` 校准完成、可用。不要将 Windows 停止共享，否则双机模式无法开始。记录 Windows 的设备 ID，供手机计算页选择。

## 正式演示：全部由你点击

| 步骤 | 在哪里操作 | 具体动作 | 应看到什么 |
| --- | --- | --- | --- |
| 1 | 手机 SoleAI | “我的” → “购物图像复核 · 手机 / 双机对照” | 图像复核入口与购物需求输入框 |
| 2 | 手机 SoleAI | 输入“500元以内的运动鞋”，点击“开始图像复核／查看上次记录” | 系统打开 Harmony 调度件的专用计算页 |
| 3 | 手机计算页 | 点击“连接并授权图像计算” | 为该工具注册独立 App，列出可选择的其他计算设备；首次注册后自动保存 |
| 4 | 手机计算页 | 点击“1. 获取真实商品图片” | 从真实购物服务检索，下载最多 30 张不同原图，显示图片数量和来源 runId |
| 5 | 手机计算页 | 选择与 Windows 调度盘一致的电脑设备 ID | 按钮显示“已选”，没有写死某台设备的身份 |
| 6 | 手机计算页 | 点击“2. 手机单机运行” | 同一批图片拆片，所有计算目标为手机；等待全部完成，记录耗时与结果校验值 |
| 7 | 手机计算页 | 不重新取图，点击“3. 手机＋电脑并行运行” | 首个真实分片交手机，其余交所选电脑；两端经原规划器准入并执行 |
| 8 | Windows 调度盘 | 查看“任务”，按手机页面的任务 ID 找到对应任务、打开追踪 | 手机与电脑都有本轮任务；查看处理过程、EXECUTE 阶段与结果状态。不要把历史任务当成本轮 |
| 9 | 手机计算页 | 等待全部完成 | 外观近似图像对、完整结果校验值，以及同输入的手机/双机耗时和单次比值 |
| 10 | 手机计算页 | 点击“4. 返回 SoleAI 查看结果” | 返回 SoleAI，展示本次摘要、相似商品线索、单次对照和结果哈希 |

**运行步骤 6—9 时，手机保持计算页前台，不锁屏、不切应用。**电脑负责展示调度盘，手机负责计算与结果。计算页属于调度件；这是为符合系统前台生命周期而做的显式衔接，不能宣传为 SoleAI 与调度件在后台无限并行。

双机是明确的**分片覆盖验收模式**：首片约束到手机，其余约束到所选电脑，仍由统一调度器完成准入和派发；不是声称规划器自动找出了最优分配。以两端实际任务和追踪确认并行，不以点击了“双机”按钮作为证明。

## 结果怎么解释

界面只有相同输入、完整结果一致且两种模式均成功时才给出单次对照。比值为 `手机耗时 / 双机耗时`，大于 1 表示这一次协同比手机快；仍建议至少三轮轮换顺序，记录温态、成功率和中位数，不挑最快一轮。

外观指数是梯度纹理与颜色的相似线索，不是概率，不证明同款。商品来自业务服务目录，不保证交易平台实时库存或售价。

## 如果停住了

- 没有新入口：03、04 尚未同时更新，先核对补丁版本。
- 手机计算能力未就绪：保持计算页前台，回到“刷新设备与恢复记录”，确认共享开启、校准完成、温控允许；不要反复新建群组。
- 没有电脑：检查 Windows 02 仍在线且共享开启、两端同空间；对照设备 ID 选择。
- 购物获取失败：检查 Wi-Fi 是否能访问业务服务；不会用写死商品自动替换真实结果。
- 任务失败或状态不明：保留本次任务 ID 和调度盘追踪，暂停性能比较。再次打开可查看保存的记录；不能把未结算的旧任务当作新任务反复提交。
- 切到后台或锁屏：调度件按原生命周期停止贡献，任务可能让出或失败。该次按中断记录，不算成功耗时。
