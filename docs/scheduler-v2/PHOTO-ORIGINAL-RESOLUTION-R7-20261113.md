# 现场照片原分辨率接入 R7

## 用户要求与行为

现场照片按原分辨率处理，不缩小输入。原有样图继续走原路径，模型和增强倍数不变；成品仍由用户点击保存到相册。

大图取消原入口的 100 万像素、1920 长边和 8 MiB 拒绝条件。手机保留原文件，运行时按 256 像素核心区和 16 像素重叠边界切块，每块复用现有照片工作流、SDK、调度器及增强模型；本机模式复用本地执行器。增强后裁去重叠区、按原坐标拼接，逐行编码完整 PNG，不降低输入分辨率。

输出保持原模型的四倍尺寸。例如 4000×3000 输入得到 16000×12000 输出，耗时和磁盘需求明显增加。几何上限为单边 32768 输入像素，仍可能受设备存储、解码能力和任务失败影响，不承诺任意尺寸均可处理。

电脑展示传输缩略预览，标注“成品预览 · 原尺寸文件在手机”；完整成品在手机保存。预览缩小不影响计算输入或保存的成品分辨率。新增大图展示记录检查每个分块 SDK 工作流已成功后才接受整图结果，不另开计算派发入口。

## 兼容范围与部署

- 当前完整大图协作展示对接鸿蒙协调中心；Windows 协调中心的大图记录接口尚未适配。
- 手机图片 App 与鸿蒙电脑协调中心的签名 HAP 已构建、覆盖安装并成功启动。
- 设备 B 继续执行原有照片分块工作流，本轮无需更新 B 的安装包。
- 小尺寸样图继续使用原 PhotoBatch；批次含大图时使用 PhotoLarge。

## 主要文件

- `apps/harmony-photo/entry/src/main/ets/PhotoFiles.ets`：原图导入。
- `apps/harmony-photo/entry/src/main/ets/PhotoLarge.ets`、`PhotoTilePlan.ets`：分块、现有工作流提交、原尺寸合成。
- `apps/harmony/scheduler/src/main/cpp/photo-png.h`、`photo-png-napi.h`：逐行 PNG 编码。
- `packages/scheduler-core/src/native-photo-engine.ts`：大图业务展示与分块回执关联。
- `apps/team-space-web/photo-display.js`：预览标识。

## 验证边界

相关回归 170 项通过，包含分块覆盖、模拟编解码及 SDK 的链路测试、失败清理和展示回执检查；宿主原生 PNG 编码测试验证尺寸、像素与文件校验。两端签名构建和安装成功。模拟链路不等于现场照片真机性能验收。

按用户要求停止扩展测试。尚未自动执行用户现场照片的整图真机处理；下一步由用户在新版图片 App 选取现场原图，点击处理，完成后手动保存。原有六张样图无需重新准备。
