# 本地真机版本独立备份 · 2026-11-12

分支：`codex/main-gpu-integration-20261112`。这是用户完成本轮测试后的本地版本备份，不合并协作者后续修改，也不覆盖 main、imageprocessing 或旧 GPU 备份分支。

## 必须保留的修改

- 手机图片 App 的就绪状态、准备计时、本机/协作模式切换及同一宿主恢复；暂停本机贡献时等待已有工作真实结算。
- 中心校准去重、独立设备并发、前后台交接、失败退避、参考任务未领取退出，避免重新等待完整超时。
- 任务推进与资源预测：派发记录进入队列估价，已结算占用及时修正，GPU 可预排队，候选可用性与剩余时间估计一致。
- B/Windows 的照片 Vulkan 四路生命周期并发、CPU/RAM/VRAM 额度一致、模型闲置保留 10 分钟及每任务模型/推理计时诊断；无用户照片或成品预计算缓存。
- R9 按近期实测纠正过时冷启动估价，确认前后队列服务时间一致；按预计完成时间选择资源，不强制平均分配，也不禁止合理 CPU 回退。
- 照片展示初始化因磁盘满/端口占用失败后，“打开真机任务展示”可按需重试，历史记录及手机仅展示连接保留。

详细约束以 `MERGE-PROTECTION.md` 的 M30～M39 和各轮证据文档为准。R9 后用户反馈已完成测试，本轮不将该反馈替换为未经重新审计的性能数字。

## 安装包

完整 Windows 中心、Windows/B 节点与手机 HAP 通过同一 GitHub Release 分发：

https://github.com/fangluyang7-debug/Harmony-cc/releases/tag/local-photo-backup-20261112-r9

- `01-Coordinator-Windows-x64.zip`：从本次源码构建，包含 R2～R9 和展示恢复。
- `02-Device-Agent-Windows-x64.zip`：普通 Windows 与 NVIDIA 设备 B 共用，内含 CPU/Vulkan 引擎和模型；GPU 是否可用取决于驱动及真实探测。
- `Harmony-Device-Agent-API24-unsigned.hap`：现有手机/鸿蒙电脑设备调度件对应的未签名构建。
- `Harmony-Photo-API24-unsigned.hap`：已安装图片 App 对应的最新未签名构建，包含就绪和模式切换修复。
- `SoleAI-Cooperative-API24-unsigned.hap`：现有 SoleAI 对应的未签名构建。
- `manifest.json`、`SHA256SUMS.txt`：各包大小、哈希、基线及来源说明。

手机 HAP 使用已有真机版本对应的构建产物，不为本次备份重新改变手机程序。设备调度件/SoleAI 构建早于图片 App，兼容本次中心协议；不得将它们描述为重新编译了本分支全部后续宿主修改。协作者在 DevEco 使用各自签名安装；本机调试签名和私钥不上传。Windows ZIP 不含用户配对身份、数据库、照片、运行历史或本地凭据。

## 验证边界与使用

历次验证结果见对应文档：R8 包含设备端并发与真实 Vulkan 参考质量，R9 58 项定向回归，展示恢复 15 项回归。打包时再次构建中心/节点并核对关键文件；不代跑用户照片，不声称新 NVIDIA 真机耗时。

中心每次启动会建立新会话，设备需重新配对。给每台设备生成独立邀请；图片 App 授权后等待绿色就绪，用同图同序同预算对照测试。照片评委页由中心启动器打开，手机本机与协作轮次在同页显示。

视频工程 `output/`、测试临时目录、签名材料、用户照片和本地数据库不属于该源码备份。磁盘清理记录保留在本地 `.test/CLEANUP-20261112.md`；未将 D 盘临时归档重新加入 Git。
