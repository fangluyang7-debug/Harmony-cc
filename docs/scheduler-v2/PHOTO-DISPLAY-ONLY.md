# 真机任务统一展示：手机单机与多设备协同

这条连接无需加入协作空间、无需 App 注册或协调者授权。手机执行本机照片内核；电脑只接收缩略图、阶段事件和已完成成品，不提供计算或派发接口。

## 手动演示

1. Windows 和手机连接同一个可互访的 Wi-Fi。
2. Windows 双击 `scripts/start-photo-display.cmd`，保持该窗口运行；已有展示服务时无需重复启动。也可在仓库根目录运行 `npm run photo:display`。
3. Windows 浏览器打开 `http://127.0.0.1:7460/`，点击“连接手机”展开二维码；大屏投放这个页面。
4. 手机打开 **Harmony 图片演示**，留在本机处理首页。在“仅展示连接”中点“扫码连接展示屏”，扫描电脑二维码。不需要打开协作空间或点击协作授权。不能扫码时可粘贴页面完整展示连接码，点击“连接”。
5. 手机从相册选择原始样例图。电脑左侧实时显示缩略图，右侧为空。点击“开始高清增强”，电脑同步展示手机的实际阶段；每张成品完成并通过哈希、尺寸校验后出现在右侧。
6. 所有照片处理完成后显示耗时、交付数量。手机成品仍在私有目录，只有点击“保存到相册”才写入系统图库。电脑可点击“导出展示记录”。

手机本机处理和协作授权是独立连接。点击开始前，应看到绿色“已连接展示屏 · Windows 不参与计算”；未连接时会明确提示“本轮仅在手机显示”。自 STATUS §116 起，首次成功连接会私有保存展示码，重开 App 自动握手恢复并继续接收端序号；主动断开会忘记该连接。电脑清空、地址改变或连接码失效时需重新扫码。未连接期间已经完成的处理过程不会被伪造为后续实时记录。

页面右上角“清空并断开”会清除本次展示记录、断开旧展示连接并生成新二维码。手机需重新扫码或输入新码；旧连接排队中的事件不会恢复已清空内容。此按钮不取消手机正在进行的本机计算，也不删除系统相册照片。

展示服务将本机已完成记录和连接码保存在 `.test/photo-display-unified/`，正常重启保持连接码；点击“清空并断开”才轮换。Wi-Fi 地址变化后重启服务并重新连接；多网卡选错时用 `npm run photo:display -- --host <Windows 的 Wi-Fi IPv4>` 指定。二维码是展示连接，不能用作协作空间邀请。

## 数据和计时口径

- 选择时发送缩略图（最长 160×120，且不超过原图边长的一半）、原图 SHA-256 和尺寸，不把计算原图预放到 Windows 执行器。
- 点击开始后，手机运行同一真实五阶段内核：分析、分块、增强、合成校验、成品交付。最多两块本机 CPU 推理并行，预算 180 秒。
- 耗时由手机单调时钟测量，包含本机流程和开始时准备展示缩略图，不包含人工选图、后续保存和异步展示传输等待。电脑接收时间另记，不能与手机时钟直接相减推算网络时延。
- 电脑记录明确为 `SOURCE_APP_REPORTED`，不冒充调度器执行回执。协同验收需另核对调度器的任务、执行目标及回执。
- 展示传输失败重试一次，随后停止发送本次队列，手机计算继续；预览生成失败也不阻止本机处理。重连后重新选图或开始下一轮，当前实现不自动补发中断期间全部结果。
- 原图并非从未在电脑出现过：现有样例由此前准备流程产生。本次“无预放”约束是新协同执行器开始前不持有计算输入或结果；展示接收端的缩略图、已完成结果不属于执行器缓存。

## 实现入口

- 展示接收服务：`scripts/photo-display-server.cjs`。
- 评委页面：`apps/team-space-web/photo-display.html`、`photo-display.js`、`photo-display.css`，复用现有 `photo.css`。
- 手机显示连接：`apps/harmony-photo/entry/src/main/ets/PhotoDisplay.ets`；入口和本机流程接线在 `pages/Index.ets`。
- 本机算法：`apps/harmony/scheduler/src/main/ets/v2/host/executors/PhotoLocal.ets`。
- 手机协作与本机共用原生 `pages/Index.ets`，协作批处理由 `PhotoBatch.ets` 接入现有 SDK；电脑评委统一使用 `photo-display.html`。服务端只读桥接：`scripts/photo-display-coordinator.cjs`；历史记录：`photo-display-records.cjs`；比较规则：`apps/team-space-web/photo-display-compare.mjs`。

最新实测和限制见 STATUS §111—§113。

## 新版协调中心入口（§113）

正式桌面入口改为 `ZhiDiaoCenter.exe`（协调中心）和 `ZhiDiaoHongShu.exe`（Windows 设备节点），不再启动旧 `Harmony.exe` 或手工测试脚本。

1. 打开新版协调中心，点击“打开真机任务展示（单机 / 协同）”。此时不必启动调度服务，手机可独立计算并仅连接展示。
2. 展示页默认仍为 `http://127.0.0.1:7460/`；手机图片 App 使用页面给出的展示二维码 / 连接码。只传展示事件不会把手机加入协作空间，Windows 也不会因此参与计算。
3. 要接续协同，启动协调中心，创建当前空间；“设备配对”生成该空间的独立邀请。每台设备分别使用一个新邀请，不重复兑换同一配对码。
4. Windows 打开设备节点程序，选择中心、输入 6 位配对码、完成配对并启动贡献；手机新版调度连接 App 扫码或输入配对码加入。图片 App 再完成业务授权。
5. 统一展示页由协调中心托管，自动读取当前空间，无需粘贴启动器地址或选择展示空间。再次创建空间会改变当前空间，设备须重新配对后才向新空间贡献；历史账本不会删除。
6. 手机调度连接 App 的“退出当前协作空间”会撤销设备及其业务 App 授权；尚有未结算任务时拒绝退出。Windows 必须先停止当前贡献，才能配对另一个空间；旧配对目录保留但不再允许通过新版启动器启动。

新版持久展示目录为用户目录 `HarmonyRuntime/photo-display`；本机迁移保留了旧单机记录和展示连接码。清空与断开只作用于展示，不能代替退出协作空间。下方手动启动器配置保留作为开发诊断流程，正式新版窗口不再显示该配置入口。

## 同一页面接续协同测试

1. 始终保持电脑 `http://127.0.0.1:7460/` 打开，不必切换到旧的 `photo.html?judge=1` 地址。
2. 页面应显示“协调中心已连接”。当前环境已配置；重新搭建时可用 `--coordinator-config <私有 JSON 文件>`（字段 `desktop` 为启动器完整 URL、`group` 为空间 ID）。也可以展开“协调中心”，粘贴本机启动器完整地址连接；此手动设置仅当前服务有效。连接凭据只在服务端，浏览器不需要先建立控制台登录会话。
3. 在 Harmony 协作空间中让手机和 Windows 加入同一空间并启用设备贡献。在图片 App 点击“连接协作空间”，完成首次授权。页面保持原来的选图、处理和成品布局，连接状态变为“已连接协作空间 · 自动规划设备分工”；已选照片保留，不再跳转另一套页面。
4. 选择与本机轮次**相同的原照片、相同顺序**，保持相同处理预算，开始协同处理。电脑统一页自动跟随新记录；任务分工来自协调中心实际节点和回执，成品实际交付后逐张显示。
5. 完成后在“每一轮，都有记录”查看各轮耗时条形图。点击一轮回看照片及分工；点击“跟随最新一轮”恢复自动跟随。
6. 比较期间不要点击“清空并断开”。该按钮隐藏清空前的展示历史并轮换手机展示码，但不删除协调中心任务回执、不退出协作空间、不取消正在运行的任务。

旧版本机事件没有上报模型和预算，因此旧记录只展示实测耗时，不自动给出严格提速倍数。照片数量、原文件哈希、顺序或尺寸不同也不会计算倍数。失败轮次保留但不参与速度比较；本机进程模拟记录不能代表多设备性能。当前3张本机36.838秒与旧1张协同19.587秒不是同输入对照。

只读观察器仅允许连接本机 `127.0.0.1` 启动器，沿用其会话认证，不增加计算提交入口。显示接收端缩略图/成品不会作为执行器预置输入。手机 App 本轮无需重新安装。
