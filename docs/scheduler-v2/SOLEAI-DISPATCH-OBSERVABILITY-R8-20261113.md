# SoleAI 调度观测与 Windows 硬件采样 R8

## 本轮结论

本次读取鸿蒙协调中心的真实记录，SoleAI 最近三次跨设备计算均为 `catalog.filter.v1`（商品筛选／比价排序），不是 GPU 照片增强。设备名称 2 是手机、3 是本机 Windows、1 是设备 B。

| 任务后缀 | 执行设备 | 后端 | 派发前 | 接单等待 | 接单至结算 |
| --- | --- | --- | ---: | ---: | ---: |
| 1772_2-817ffc40… | 1（B） | CPU | 271 ms | 148 ms | 203 ms |
| 9374_3-83397e80… | 1（B） | CPU | 202 ms | 152 ms | 228 ms |
| 0076_4-9365556f… | 3（Windows） | CPU | 243 ms | 305 ms | 573 ms |

三项均有 SUCCEEDED 回执。接单至结算包含传输、计算、输出等时间，不能当作纯 CPU 计算耗时。这类亚秒任务可能完全落在调度盘两秒刷新间隔之间，完成后额度立即释放，因此进度条不明显变化不等于没有派发。完整业务耗时还包括商品 API 请求，不能把全流程时间归给设备计算。

## 修改内容

1. 鸿蒙协调中心从 CpuJob 读取任务、目标和规划信息，展示能力名称、源设备→执行设备、CPU/Vulkan 后端、阶段状态、阶段时间、规划原因和 Trace ID。近期任务保留在设备资源页；任务追踪中区分应用观测与真正派发。
2. 新增认证的 `/v2/devices/me/telemetry`，凭配对身份绑定设备。观测不改变额度、准入或调度算法，不替代执行回执。
3. Windows 节点后台约三秒采集整机 CPU 时间差、内存、NVIDIA 驱动 GPU 利用率和温度。电池通过系统 CIM 接口约三十秒采集。慢传感器查询不阻塞任务派发；不支持新接口的旧中心报错后退避。
4. 无电池显示无电池；无传感器保持未提供。GPU 温度单独标注，不冒充 CPU 温度或鸿蒙系统热等级。整机 CPU 占用不等于调度槽位，也不能独立归因为 SoleAI。

## 部署与使用

鸿蒙电脑协调中心 HAP 已覆盖安装并恢复服务。本机 Windows 节点已更新 host.js、allotment-client.js、device-telemetry.js，正常停止后重启，原配对保留。实测接口返回本机 CPU、内存、电量 100%、外接电源；这是空闲/当前系统观测，不是新的 SoleAI 性能成绩。

设备 B 需要应用 `dist/02-Device-Agent-Telemetry-R8-20261113.zip` 补丁：停止并退出原节点，解压，将 services 文件夹覆盖到与 ZhiDiaoHongShu.exe 同级的原目录，然后开启节点。保留原模型、GPU 引擎和配对。补丁不独立运行，仅适用于当前已有完整节点包。本轮未在 B 上安装，GPU 温度和利用率实际采集待 B 更新后确认。

演示时在鸿蒙中心打开“设备资源”，看实时采样和“近期分配到本设备的任务”；打开“任务追踪”，看手机→执行设备、计算能力、状态和回执耗时。SoleAI 手机 App 本轮无需重装。保持 SoleAI 前台并恢复协作连接即可提交新的普通购物任务。
