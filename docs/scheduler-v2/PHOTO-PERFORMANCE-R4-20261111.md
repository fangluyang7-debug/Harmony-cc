# 照片阶段推进、成本学习与批次并发优化 r4

日期：2026-11-11。分支：`imageprocessing`，基于 `df79a6b` 后的现有真机工作区继续修改，未覆盖此前修改。本轮按用户要求更新应用，由用户手动复测同六张照片；没有自动运行新的真机照片任务。

## 依据与目标

上一轮用户六图协作 `5938557c-855c-45b9-bfb1-fac0dbdcf7a3` 为 43.251 秒，手机本机 `baffad9d-90a5-4fb3-88df-7f1c63f23872` 为 63.558 秒。原图哈希集合相同，部分顺序不同；这是上一版本的实测，不是本轮优化成绩。详细审计保留在 r3 文档。

固定两图窗口使后四图较晚开始，阶段轮询重复查询数据库；鸿蒙回执没有拆分初始化开销，成功执行耗时因此未被成本历史接收。本轮针对这些缺口调整，保留相同模型、图像质量、180 秒批次总预算和真实调度路径。

## 修改内容

| 目标 | 实现与位置 | 必须保留的边界 |
| --- | --- | --- |
| 减少阶段等待 | `services/coordinator/src/cpu-jobs.ts` 新增 `graphProgress`：同一工作流的已提交节点以一个 SQL 语句读取归属、当前执行者、队列、回执和提交状态；`workflow-jobs.ts` 使用批量结果推进 | 参数化查询、单语句快照；仍核对空间/主体/宿主、备份赢家、成功回执、输出哈希引用和可用性；不能把 RUNNING 当完成，不重复启动已准入节点 |
| 学习真实成本 | `performance-feedback.ts` 接收未拆分 overhead 的成功已提交 EXECUTE 样本，标注 `executionTotal`；`packages/scheduler-core/src/planning-api.ts` 使用完整耗时时不再次叠加冷启动估计 | 与分拆计时样本分组隔离，按 workKey/config/startup/执行身份/校准代次匹配；至少 3 个有效样本，10 分钟 TTL，最多 32 条窗口；非提交和失效样本仍排除 |
| 扩大批次流水 | `planning.ts` 的能力统计增加去重后的活跃物理设备数；`PhotoSession.ets` / `PhotoBatch.ets` 以设备数加一决定窗口，上限 4，旧服务或读取失败回退 2；中心工作流推进并发从 2 增至 4 | 一个设备的多个目标不能冒充多台设备；一/二/三台对应 2/3/4 图窗口；每图最多 4 个就绪节点；真实计算准入仍由设备总账和 App 额度控制，不等于无限启动线程 |

更大的图窗口用于使分析、传输、增强、合成重叠，不强制平均分配设备，也不保证每台都被规划器选中。最终仍按计算、传输、队列与预算选择目标。此次没有降低手机单机基线配额，没有预放图片或预计算成品，没有改变照片模型/分片及输出质量。

## 更新与手动复测

Windows 已安装协调中心更新了工作流、成本反馈、能力统计及共享规划器；手机图片 App 已覆盖安装新版，恢复原协作空间连接。鸿蒙电脑继续使用上一版有效执行器，本轮没有变更其原生引擎。中心和 Windows 节点已重启加载新代码，配对信息和历史记录保留。

部署后只读核对：三台设备均出现有效期内的 `photo.enhance.v1` 候选（Windows / 鸿蒙电脑 `parallel-8`，手机 `parallel-4`），手机界面明确显示已连接；中心最新照片批次仍为用户的 `5938557c-855c-45b9-bfb1-fac0dbdcf7a3`，本轮未新增真机照片执行。6 个分发包 SHA256 校验通过，中心和共享规划器构建产物、已安装文件与 ZIP 内文件逐字节一致。

本地分发目录仍为 `dist/调度系统分发-20261111-r2/`（目录名保留以兼容现有交付路径），01/02 ZIP、05 图片 HAP 与 `SHA256SUMS.txt` 同步；03 调度 HAP 本轮未变更。签名 HAP 仅适用已授权设备；源码、包和 GitHub 推送是不同步骤，本轮未新增推送。

用户复测：

1. 保持三台设备在同一可互访 Wi-Fi，Windows 节点运行、鸿蒙电脑调度 App 前台、手机图片 App 前台。
2. 调度盘确认三个设备在线且照片能力就绪。手机确认“已连接协作空间 · 自动规划设备分工”。
3. 更新会关闭旧页面，请重新选择相同六张 192×128 原图，尽量保持相同顺序，点击开始高清增强；保持原 180 秒预算。
4. 结束后保留电脑展示页记录，不清空历史。根据真实尝试回执检查增强分片在哪些设备执行、成功交付数与整批耗时。
5. 如需新的手机基线，切换“改用本机处理”，用相同六张图再运行；仅展示连接不参与计算。避免同时执行其他批次。

## 仍待新证据的问题

本轮尚无用户六图真机耗时，不能宣称进一步提速。历史样本到期或重建执行身份后，规划仍回到校准先验，累计有效样本后再学习。当前照片 workKey 沿用输入字节分桶，对不同几何尺寸/内容的精确计算量预测仍有限；本轮不改动跨端契约。源端合成的多输入汇聚路径仍保留，后续应根据新 trace 决定是否值得改为设备间直接汇聚，不能提前删除交付与完整性证据。
