## 1. 本轮落地效果

首页先呈现创建、加入和我的空间；进入空间后才呈现仪表盘。成员可以返回首页、重新进入空间，关闭网页不影响云端协调服务与设备代理。

| 功能 | 当前效果 |
| --- | --- |
| 账号 | 名称、账号、密码注册与登录；同一账号可从不同浏览器登录，服务端保存空间成员关系 |
| 创建空间 | 创建持久化空间，创建者成为负责人 |
| 加入空间 | 负责人生成 24 小时有效的邀请链接/码；加入后成为协作成员或观察者 |
| 成员 | 显示成员及其登记设备数量；负责人可切换协作成员/观察者角色 |
| 设备接入 | 在页面填写名称、CPU 和内存贡献上限、共享模式，在线生成一次性设备邀请和共享配置，不再要求停止服务进行离线预配 |
| 可插拔连接 | 运行已有 PC Agent 后自动连接、上报、能力检查；断线重连继续使用原安装目录和账本；过期上报不计为在线 |

| 界面适配 | 桌面首页、桌面空间内页面、390px 手机尺寸已做浏览器检查 |

## 2. 云端与本地的职责

Railway 中的协调服务维护空间、成员、设备目录、能力证据、配额、任务选择、派发及回执。成员电脑不是团队的中心服务器。

设备代理在设备上运行，负责本机采样、原生操作系统允许范围内的资源准入、CPU 执行、暂停让步和账本恢复。浏览器页面是控制终端；手机打开网页不会自动贡献 CPU/GPU。

“云端操作系统”是产品类比。本轮实现的是跨设备的上层协调服务，不是把多个系统内核、显存或任意进程透明合并。当前任务选择沿用已具备能力中的单节点 CPU 路径，没有宣称完整 DAG 全局最优规划已经接入。

`scripts/prepare-space-deploy.ps1` 将明确列出的源文件整理到新的 `.test/space-deploy-*` 目录，再按该目录作为部署根上传。它不上传本地数据库、测试账号、代理凭据、环境文件和历史构建。云端通过 CLI 上传部署，尚未配置 GitHub 自动部署。

## 4. 实际操作

1. 打开线上入口并注册自己的 Harmony 账号（与 Railway 账号无关）。
2. 创建空间，在空间内生成成员邀请，分享给协作者。
3. 协作者注册/登录自己的 Harmony 账号后，使用链接或邀请码加入。
4. 在要贡献电脑资源的成员账号下点击“接入设备”，填写资源贡献设置。
5. 下载 `invitation.json` 和 `contribution.json`，放到该电脑的最新 Harmony 项目根目录。
6. 使用页面提供的配对和启动命令。需 Node.js 22 或以上；预先建立安装目录的父目录。一次性邀请 10 分钟内有效。配对后的 `agent.json` 与账本必须保留，重连不要重新创建空账本。
7. 等待设备在线且能力检查完成，在任务中心发起任务；首次接入时可能短暂显示“检查中 / 等待资源”。
8. 用设备暂停共享验证变化。离线设备的设置会在重连后同步。

账号密码不包含邮箱验证/密码找回，当前请自行妥善保存账号。设备接入仍使用命令行代理，图形安装器尚未提供。

## 5. 新接口边界

浏览器统一使用 `/v2/spaces`，HttpOnly 会话 Cookie；修改接口使用 JSON，验证浏览器 Origin。浏览器账号没有拿到可用于任意设备执行的凭据。

| 方法与路径 | 用途 |
| --- | --- |
| POST `/register` | `{account,name,password}` 注册并登录 |
| POST `/login`、`/logout` | 登录、退出当前会话 |
| GET `/me` | 当前用户及其空间列表 |
| POST `/` | `{name}` 创建空间 |
| POST `/join` | `{code}` 加入邀请所属空间 |
| GET `/:spaceId` | 当前空间快照：成员、设备、任务和协调者信息 |
| POST `/:spaceId/invites` | 负责人生成 MEMBER / VIEWER 邀请 |
| POST `/:spaceId/members/:userId` | 负责人修改非负责人角色 |
| POST `/:spaceId/devices` | 生成绑定当前成员和空间的设备邀请；同时确认贡献预算 |
| POST `/:spaceId/devices/:deviceId` | 设备所有者或负责人修改共享模式；已有资源上限保持不变 |
| POST `/:spaceId/jobs` | `{requestId,capability,input,targetId?}`，登记输入、写入校验后的工件、调用既有 CPU 派发流程 |
| GET `/:spaceId/jobs/:jobId` | 发起者读取任务状态与已提交成功结果 |
| POST `/v2/device-settings` | 设备凭据读取自身共享设置，返回 `{settings: ... 或 null}`，兼容非空间预配设备 |

成员/设备/任务均按空间隔离；观察者不可接入设备或发起任务；负责人不能借查看团队任务列表读取其他成员的结果正文。

## 6. 明确留下的后续接口工作

- GPU 优先供给指定成员、优先级队列和完整 DAG 规划尚未接入网页任务路径；不提供只改变显示、不改变调度的假开关。
- 鸿蒙原生手机贡献算力、GPU 执行、手机 SDK 真机验收后续推进。
- 通用应用注册/SDK、应用级配额、任务取消/重规划、长会话与流式任务继续使用既有协议作为接口基础，本轮未宣称完成。
- 设备重命名/删除、成员移除/退出、负责人转移、邀请撤销 UI、在线调整已登记设备容量及图形安装器待补。
- 当前资源条展示协同任务占用与可准入资源，不是整机 CPU 百分比，也没有把未知 GPU 利用率显示为 0%。
- 当前团队任务列表面向演示规模，尚无分页与历史归档功能。

## 7. 验证记录

测试覆盖账号登录、邀请、权限与跨空间隔离、设备配对、自动能力检查、真实 CPU 文本执行与结果回传、共享暂停、服务重启后空间/登录身份持续存在，以及公网证书与签名身份分离。

- 协调服务完整回归：52/52 通过；随后公网修复相关远程评估/空间联调 4/4 通过，CPU Host/空间联调 2/2 通过。
- PC Agent：34/34 通过（包含新增未准入检查任务的持久化拒绝与回报重试）。
- 架构检查：18/18 通过；工件传输包测试：1/1 通过。
- 设备时钟人为快 2.5 秒的完整空间执行测试：1/1 通过。代理使用受 HTTPS 保护的服务器 Date 响应保守换算采样时间，不修改硬件实测数值，也不放开未来采样校验。
- Railway 公网软件链路：HTTPS 配对、WSS 控制、自动能力检查、CPU 任务、工件结果、云端暂停全部通过。`Hello cloud` 返回 `characters=11, words=2, lines=1`。结果见本地 `.test/cloud-space-SenYFS/result.json`，代理正常结束并撤销测试凭据。
- 真实公网验证曾发现设备时钟偏差导致上报拒收，以及领取检查任务后未准入而无法结算的情况；前者用服务器时间基准换算解决，后者只在确定没有持久化准入时记录未执行结果。已准入而状态未知的任务仍保留账本和对账语义。

日志位于本地 `.test/team-*.log`。云端软件验证脚本 `scripts/smoke-team-space-cloud.cjs <Harmony HTTPS地址>` 创建独立的私有测试空间，只用有限 CPU/内存执行内置参考任务；结束后停止代理并撤销临时设备凭据。测试账号凭据留在被 Git 忽略的 `.test/cloud-space-*` 中，不写入本交接文档。

本轮没有进行鸿蒙 SDK、手机、CUDA GPU 或多台物理设备的验收。线上 REAL 表示使用真实设备采样域，不等同于上述专项验收完成。
