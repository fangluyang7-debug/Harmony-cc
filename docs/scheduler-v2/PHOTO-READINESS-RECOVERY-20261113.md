# 图片 App 偶发就绪等待恢复修复

日期：2026-11-13；沿当前本地版本修改，不拉取或覆盖协作者代码。

## 现场证据与结论

用户报告偶发持续等待。本轮检查时手机最初在本机模式，未保留用户此前卡住当时的完整日志，不能断言每一次卡住都由同一原因引起。

本轮切回协作时实际观察到 `Operation timeout`；同一时段 Windows 中心该图片宿主的五项照片能力均为 ACTIVE/EVALUATION_PASSED，随后手机恢复就绪。这证明状态查询超时也会表现为“尚未就绪”，不能一概解释为模型未完成校准。查询前的最近一轮手机本机六图日志完整结束，未发现遗留正在执行的照片任务。

代码核对并复现的恢复缺口：

1. 控制 socket 建立后，Hello/Recovery 确认未完成时，旧 socket 阻止再次 connect，缺少握手截止时间。
2. 中心已将参考任务标记 CLAIMED，但手机未收到领取响应；下次领取为 RECONCILE，同一运行代次没有本地接单记录时旧代码不回复，校准可能一直等待结算。
3. 就绪探测缺少整体截止和操作入口。失效 App 授权与普通控制重连混在一起，用户不能判断是否应继续等。

## 修复

- NativeAgent 对未完成握手的连接设置 20 秒重建条件，仅更换 socket，保留身份、账本和待确认消息，继续原协议恢复；不强制重建模型或 ledger。
- 校准串行执行链上，对同一实例、同一 ledger 代次、无接单记录、无运行记录、无其他正在进行的准入、无既存结果的 RECONCILE，持久化并上报 notRun。旧任务实际接单/运行时不使用此路径；保存过的拒绝沿原持久化重试链路发送。不上报成功，不跳过真实参考校准。
- 资格和 App 身份 HTTP 查询增加 12 秒硬截止并释放请求；此截止不应用到照片上传/下载。页面就绪轮询增加 30 秒兜底，忽略上次轮询迟到的结果；离开页面清理计时器。
- 控制未恢复时每隔至少 5 秒核对一次鉴权 App 身份，明确发现过期或撤销。正常控制在线时不增加这条身份查询。
- 超时、等待过长显示“重新检查连接”；授权、证书或已停止宿主提示“重新授权当前协作空间”。就绪仍依赖五项真实资格；不采用固定延时标绿。
- 增加 READINESS_STATE 状态变化日志，记录原因和准备耗时。Toast 失败不能反过来令能力检查失败。
- 保留单机处理、独立展示连接、模式切换保留代理、业务预算与真实计时、用户手动保存相册。
