## 2. 本轮已经接通的链路

1. **直传失败后按需中继。** 下游尚未派发时独立准备输入，用同一规划器比较 B→中继→C；两跳成本、剩余期限和中继并发进入计划。完整收货前不启动计算，已提交 B 不被重算。
2. **预派发改派与 C 副本供 D 使用。** 调用方明确指定目标的约束保留；没有硬性指定时可重新选择目标。B 端点换代后，C 已确认的同 App 完整副本仍可供 D 使用，保留 B 的生产血缘。
3. **缺失和容量故障。** 认证报告绑定具体授权/交付事项与完整 ref。普通超时不会删除目录证据。无可行来源或剩余预算不足会给出可区分原因；中继缓存满可在原期限内明确失败，不靠耗尽预算结束。
4. **持久化保留与实际回收。** 从工作流、依赖、真实结算与在途授权重建保留关系；最后一个使用者结束后清理目录、描述和字节文件。未结算读者受保护。端点换代后的库存清单仅用于回收。
5. **结果领取与来源计时。** SDK 完整读取和校验后确认领取；同一任务对象重复取结果复用已校验字节。来源原始提交至完整结果校验用同域单调时钟计时，恢复对象没有原起点时保持未知。最终输出领取窗口为原截止后五分钟与制品硬期限中较早者。
6. **因果追踪。** 查询投影关联来源根、已提交前置、派发、校验收货和同进程副本转交。发送方完整 HTTP 区间与接收方就绪时刻分别保留，累计传输工作量按权威区间去重。追踪异步、有界，不阻塞数据响应或传输槽位释放。
7. **成本核对与调度盘。** 保存规划时 EXECUTE、QUEUE、PUBLISH 估计，按同快照/目标对照实测并保留正负误差；只读调度盘增加因果依赖和分段估计折叠区。

完整跨域关键路径与残差仍存在计量缺口，页面保留 UNKNOWN。已测因果链、单段误差、来源 SDK 端到端计时分别展示，不能合计为优化收益。

正式 SDK 整图覆盖正常直传、响应丢失、直连隔离、接收端缓存满、生产端缓存满、中继缓存满及双图竞争。成功图保持三个计算 attempt；中继全满负例只保留前两个已成功提交的计算，第三项未启动。另有协调者加三个独立宿主进程的 C→D 改派，B 换代后由 C 供数，仍只有三个计算 attempt。

这些是**单物理 PC 上的本地 TLS/独立进程软件测试**，选择成本和链路条件包含 SIMULATED 注入。它们不是实际 AP 隔离、多物理设备 Wi-Fi 时延、GPU 或手机验收，也没有形成性能收益结论。

开发中曾出现协调者 99/103 和容量阶段 103/105；原因及修复见 STATUS §44–45，最终 106/106 已覆盖相关回归。尤其注意：输入准备仅处理尚无 attempt/outbox 的节点；已有派发后不能因后续副本或容量变化重规划并错误取消该计算。
