## 四组职责

| 目录 | 使用方式 | 职责 |
| --- | --- | --- |
| 01-Coordinator-Windows-x64 | 完整解压，双击 Start.cmd | 启停局域网协调中心、规划调度、空间和仪表盘 |
| 02-Device-Agent-Windows-x64 | 完整解压，双击 Start.cmd | Windows 应用内接入、确认共享、执行任务 |
| 03-Device-Agent-HarmonyOS | 安装匹配系统和签名的 HAP | 鸿蒙接入、扫码、贡献资源、App 授权和应用内调度盘 |
| 04-SoleAI-HarmonyOS | 安装独立 HAP | 以独立 App 身份，经 SDK 提交业务任务 |

同一台 Windows 可同时运行 01 和 02，分别承担协调和执行角色。不要再启动旧命令行设备代理。短码、单设备单空间和原有身份恢复逻辑保留。03 与 04 是两个 App；目前手机切到 SoleAI 前台时，设备调度件停止贡献，手机仍可作为任务来源，其他在线设备负责执行。

01/02 内置 Node/Electron，无需接收者另装 Node、npm。01 首次生成证书仍需本机 OpenSSL；这不是无前置依赖的安装器。Windows 包尚无代码签名。03/04 本次提供的是 **API 24 调试签名包**，只能安装到签名描述文件授权的设备，不是通用发行签名；仓库正式 API 22 基线未改动，不能以此声称 API 22 验收通过。

## 构建

先完成现有协调者及工作区依赖编译，再运行 `npm run desktop:build`。原生 HAP 需事先用对应 SDK 构建并签名；脚本不会生成或传播开发者私钥。

在仓库根目录 PowerShell 中设置：

```powershell
$env:HARMONY_AGENT_HAP = '<设备调度件 HAP 的绝对路径>'
$env:HARMONY_AGENT_HAP_API = '24'
$env:HARMONY_AGENT_HAP_SIGNED = '1'
$env:SOLEAI_HAP = '<SoleAI HAP 的绝对路径>'
$env:SOLEAI_HAP_API = '24'
$env:SOLEAI_HAP_SIGNED = '1'
npm run distribution:build -- 'dist/调度系统分发-新目录'
```

输出目录必须不存在。未提供 HAP 时对应目录标记 NOT_BUILT，不能作为可安装包交付。脚本打包已编译 JS，保留 Nest 元数据和 Prisma 迁移，复制原生 sharp 依赖；生成两个 Windows ZIP、原生 HAP、构建清单和 SHA-256 校验表。构建清单记录源码哈希和脏工作区状态。不要分发本机数据库、身份缓存或签名私钥。

本轮最终目录为 `dist/调度系统分发-20261108-final`。其余 integrated、v2、v3 是排错草稿，不应分发。升级已有中心时，可在启动前显式设置 `HARMONY_COORDINATOR_DATA_DIR` 指向原中心目录，先停旧中心并备份；不要启动两个进程访问同一数据库。新部署默认创建独立数据目录。

## 可现场操作的演示

1. Windows 01 启动中心，02 与两台鸿蒙的 03 接入同一空间，确认共享并保持前台；在应用内调度盘查看真实设备与任务。
2. 手机打开 SoleAI →“我的”，开启协同。首次使用由设备调度件确认独立 App 授权，再返回 SoleAI。本轮图片声明修订为 `soleai.image.2`，旧安装不会被静默扩大权限。
3. 点击“演示图片预处理”。应用生成内置样例输入，沿既有 `preparePhoto → SchedulerSdk → PlanningService` 提交；完成后展示实际执行目标和返回图片。调度盘可核对同一任务和 trace。
4. 做三设备执行矩阵时，先将手机切回设备调度件前台。SoleAI 前台提交成功不代表手机同时作为后台执行器贡献。

样例演示无需 CUDA，也不依赖购物业务后端；它验证的是独立 App 的 CPU 图片预处理，不能宣称完整商品检索通过。新声明区分 `image.crop.v1` 能力与 `image.crop.contract` 授权合同，实际任务授权仍由原接口校验，没有新派发入口。
