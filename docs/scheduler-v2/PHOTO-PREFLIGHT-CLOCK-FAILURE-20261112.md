## 根因与复现

在 `c65def3` 引入、于本地整合为 `97c2595` 的派发复核逻辑中，CpuJobs 在调用 preflight 之前创建 `{ now: Date.now(), ... }`。preflight 随后异步读取数据库快照，再用先前的 now 重新规划。

若读取期间心跳/其他任务发布了新快照，就可能出现：

1. 调用方记录 now = 100。
2. 异步读取期间，新快照 capturedAt = 104。
3. 读取完成时已是 105，但规划器仍拿 now = 100 校验。
4. 合法快照被 `snapshot.capturedAt > clock.now` 判为非法，抛出 `SNAPSHOT_OR_POLICY_INVALID`。
5. 工作流将该异常作为终止原因，取消其他分块。

这属于本次保留的 GPU r3 调度优化代码的缺陷。此前回归测试更新了快照版本，但 capturedAt 一直固定为 100，没有覆盖真实时间随异步读取推进的场景。

已加入确定性复现：旧的调用顺序产生与真机记录相同异常；新调用方式在快照读取完成后才采样时钟。真正来自未来的快照仍拒绝，不关闭时间校验，也不把所有非法策略错误一概当成可重试。
