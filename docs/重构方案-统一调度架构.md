# 智调鸿枢 统一调度架构重构方案

## 一、核心架构原则

### 1.1 三层调控体系

```
┌─────────────────────────────────────────────────────────────┐
│  云端宏观调度中枢 (Cloud Macro Scheduler)                      │
│  - 读取所有接入终端设备的实时画像                                │
│  - 读取外部App的AI任务画像                                      │
│  - 执行全局调度算法,选择最优设备分配方案                          │
└─────────────────┬───────────────────────────────────────────┘
                  │
        ┌─────────┴─────────┬─────────────┬──────────────┐
        ▼                   ▼             ▼              ▼
   ┌─────────┐        ┌─────────┐   ┌─────────┐    ┌─────────┐
   │ Phone A │        │ Phone B │   │ Worker  │    │  Cloud  │
   │ 微观调度 │        │ 微观调度 │   │  资源   │    │  Runtime│
   └─────────┘        └─────────┘   └─────────┘    └─────────┘
        │                   │             │              │
   设备内部硬件       设备内部硬件    独立进程       云端算力池
   资源调控           资源调控        资源准入
```

### 1.2 设备画像生成机制

**外层(设备级):**
- 每个终端设备定时(或事件触发)向云端上报设备画像
- 设备可自由插拔,云端动态维护在线设备列表
- 画像包含:设备ID、设备类型、支持能力列表、资源快照、硬件特征、网络性能

**内层(设备内硬件):**
- 每个终端内部维护「可调用硬件清单」
- 实时监测:CPU核心数与使用率、内存可用量、热状态、电量、后端可用性(CPU/GPU/NPU)
- 不需要穷尽所有芯片参数,关键指标:可用执行槽位、内存预算、历史任务耗时

### 1.3 AI任务画像

外部App接入时生成任务画像:

```typescript
import { Injectable } from '@nestjs/common';

export interface UnifiedDeviceProfile {
  deviceId: string;
  deviceType: 'PHONE' | 'WORKER' | 'CLOUD' | 'EDGE';
  capabilities: string[];  // ['image.crop.v1', 'image.embedding.v1', ...]
  
  resourceSnapshot: {
    availableSlots: number;
    totalMemoryMB: number;
    availableMemoryMB: number;
    thermalLevel?: 'NORMAL' | 'WARM' | 'HOT' | 'CRITICAL';
    batteryPercent?: number;
    cpuUsagePercent?: number;
  };
  
  hardwareProfile: {
    backends: ('CPU' | 'GPU' | 'NPU')[];
    cpuCores?: number;
    cpuArchitecture?: string;
    // 避免过度细化,关键是实测执行性能
  };
  
  networkProfile: {
    uploadMbps: number;
    downloadMbps: number;
    rttMs: number;
    measuredAt: number;
  };
  
  executionHistory: {
    capability: string;
    sampleCount: number;
    meanMs: number;
    p95Ms: number;
    failureRate: number;
    lastExecutedAt: number;
  }[];
  
  observedAt: number;
  ttlMs: number;
  source: 'REAL' | 'SIMULATED';
  trusted: boolean;
}

@Injectable()
export class UnifiedDeviceRegistryService {
  private devices = new Map<string, UnifiedDeviceProfile>();
  
  // 设备主动注册(Phone通过HAR上报,Worker启动时注册)
  registerDevice(profile: UnifiedDeviceProfile): void {
    if (!this.validateProfile(profile)) {
      throw new Error('INVALID_DEVICE_PROFILE');
    }
    this.devices.set(profile.deviceId, profile);
    this.scheduleExpiry(profile.deviceId, profile.ttlMs);
  }
  
  // 更新设备状态(增量更新)
  updateDeviceState(deviceId: string, patch: Partial<UnifiedDeviceProfile>): void {
    const existing = this.devices.get(deviceId);
    if (!existing) throw new Error('DEVICE_NOT_REGISTERED');
    
    Object.assign(existing, patch, { observedAt: Date.now() });
    this.devices.set(deviceId, existing);
  }
  
  // 查询支持特定能力的设备
  getDevicesForCapability(capability: string): UnifiedDeviceProfile[] {
    const now = Date.now();
    return Array.from(this.devices.values())
      .filter(d => 
        d.capabilities.includes(capability) &&
        d.trusted &&
        d.source === 'REAL' &&
        now - d.observedAt < d.ttlMs
      );
  }
  
  // 设备主动注销或TTL过期
  unregisterDevice(deviceId: string): void {
    this.devices.delete(deviceId);
  }
  
  private validateProfile(profile: UnifiedDeviceProfile): boolean {
    return !!(
      profile.deviceId &&
      profile.capabilities.length > 0 &&
      profile.resourceSnapshot.availableSlots >= 0 &&
      profile.observedAt > 0 &&
      profile.ttlMs > 0
    );
  }
  
  private scheduleExpiry(deviceId: string, ttlMs: number): void {
    setTimeout(() => {
      const device = this.devices.get(deviceId);
      if (device && Date.now() - device.observedAt >= ttlMs) {
        this.unregisterDevice(deviceId);
      }
    }, ttlMs);
  }
}
```

### 2.2 通用AI任务调度入口

**修改文件:** `services/api-server/src/core/runtime/unified-task-scheduler.service.ts`

```typescript
import { Injectable } from '@nestjs/common';
import { UnifiedDeviceRegistryService, UnifiedDeviceProfile } from './unified-device-registry.service';
import { WorkflowPlacementPlanner, PlacementCandidate } from './workflow-placement-planner';
import { ArtifactRef } from './scheduling-protocol';

export interface AITaskProfile {
  taskId: string;
  capability: string;  // 'image.crop.v1', 'nlp.embedding.v2', 任意capability
  
  modelRequirements?: {
    modelId: string;
    modelVersion: string;
    backend?: ('CPU' | 'GPU' | 'NPU')[];
    minimumQuality: number;
  };
  
  resourceRequirements: {
    memoryMB: number;
    budgetMs: number;
    privacyLevel: 'PUBLIC' | 'PRIVATE' | 'SENSITIVE';
  };
  
  inputArtifacts: ArtifactRef[];
  outputSpec: { schema: string; estimatedBytes: number };
  
  context: {
    userWaiting: boolean;
    userVisible: boolean;
    importance: number;
  };
}

export interface DeviceAssignment {
  taskId: string;
  assignedDeviceId: string;
  assignedExecutorId: string;
  baseline: { deviceId: string; estimatedMs: number };
  suggestion: { deviceId: string; estimatedMs: number; reason: string };
  actualChoice: { deviceId: string; reason: string };
  mode: 'BASELINE' | 'OPTIMIZED' | 'FALLBACK';
}

@Injectable()
export class UnifiedTaskSchedulerService {
  constructor(
    private readonly deviceRegistry: UnifiedDeviceRegistryService,
    private readonly planner: WorkflowPlacementPlanner
  ) {}
  
  async scheduleTask(task: AITaskProfile): Promise<DeviceAssignment> {
    // 1. 获取所有支持该capability的设备
    const candidateDevices = this.deviceRegistry.getDevicesForCapability(task.capability);
    
    if (candidateDevices.length === 0) {
      throw new Error(`NO_DEVICE_SUPPORTS_CAPABILITY: ${task.capability}`);
    }
    
    // 2. 转换为调度算法的候选格式
    const candidates: PlacementCandidate[] = candidateDevices.map(device => {
      const history = device.executionHistory.find(h => h.capability === task.capability);
      
      return {
        deviceId: device.deviceId,
        executorId: this.inferExecutorId(device),
        capability: task.capability,
        trusted: device.trusted,
        source: device.source,
        observedAt: device.observedAt,
        ttlMs: device.ttlMs,
        
        availableSlots: device.resourceSnapshot.availableSlots,
        availableMemoryBytes: device.resourceSnapshot.availableMemoryMB * 1024 * 1024,
        
        quality: this.assessQuality(device, task),
        computeMs: history?.meanMs ?? this.estimateColdStart(device, task),
        queueMs: 0, // 实时查询或估算
        coldMs: history ? 0 : 50,
        uncertaintyMs: history ? (history.p95Ms - history.meanMs) : 0,
        publishMs: 0
      };
    });
    
    // 3. 获取数据位置信息
    const dataLocations = await this.locateArtifacts(task.inputArtifacts);
    
    // 4. 构建网络拓扑
    const links = this.buildNetworkTopology(candidateDevices);
    
    // 5. 调用统一调度算法
    const planResult = await this.planner.plan({
      nodes: [{
        id: task.taskId,
        capability: task.capability,
        dependencies: [],
        inputs: task.inputArtifacts.map(a => a.id),
        output: { id: task.taskId + '-output', bytes: task.outputSpec.estimatedBytes },
        baselineDeviceId: this.selectBaseline(candidates),
        memoryBytes: task.resourceRequirements.memoryMB * 1024 * 1024,
        minimumQuality: task.modelRequirements?.minimumQuality ?? 0,
        candidates
      }],
      artifacts: dataLocations,
      links,
      remainingBudgetMs: task.resourceRequirements.budgetMs,
      finalDestination: 'cloud-runtime', // 或根据任务来源确定
      networkAllowed: task.resourceRequirements.privacyLevel !== 'SENSITIVE',
      privacy: task.resourceRequirements.privacyLevel
    });
    
    // 6. 应用门禁策略
    const authorized = this.authorizePlacement(planResult, task);
    
    return {
      taskId: task.taskId,
      assignedDeviceId: authorized.actualDeviceId,
      assignedExecutorId: authorized.actualExecutorId,
      baseline: planResult.baseline,
      suggestion: planResult.suggestion,
      actualChoice: authorized,
      mode: authorized.mode
    };
  }
  
  private inferExecutorId(device: UnifiedDeviceProfile): string {
    switch (device.deviceType) {
      case 'PHONE': return 'mobile-har-executor';
      case 'WORKER': return 'cpu-worker';
      case 'CLOUD': return 'cloud-runtime';
      default: return 'generic-executor';
    }
  }
  
  private assessQuality(device: UnifiedDeviceProfile, task: AITaskProfile): number | null {
    // 基于历史执行记录和设备类型评估质量
    const history = device.executionHistory.find(h => h.capability === task.capability);
    if (!history || history.sampleCount < 5) return null;
    
    // 质量 = 成功率 × 设备可靠性因子
    const successRate = 1 - history.failureRate;
    const deviceFactor = device.deviceType === 'CLOUD' ? 1.0 : 0.95;
    return successRate * deviceFactor;
  }
  
  private estimateColdStart(device: UnifiedDeviceProfile, task: AITaskProfile): number {
    // 冷启动估算:基于设备类型和任务复杂度
    const baseMs = task.resourceRequirements.budgetMs * 0.5;
    const deviceMultiplier = {
      'CLOUD': 1.0,
      'WORKER': 1.2,
      'PHONE': 1.5,
      'EDGE': 1.3
    }[device.deviceType] ?? 1.5;
    
    return baseMs * deviceMultiplier;
  }
  
  private selectBaseline(candidates: PlacementCandidate[]): string {
    // 选择质量最可靠的作为基线(通常是云端)
    const withQuality = candidates.filter(c => c.quality !== null);
    if (withQuality.length === 0) return candidates[0].deviceId;
    
    return withQuality.reduce((best, curr) => 
      (curr.quality ?? 0) > (best.quality ?? 0) ? curr : best
    ).deviceId;
  }
  
  private async locateArtifacts(artifacts: ArtifactRef[]): Promise<any> {
    // 查询每个artifact在哪些设备上有副本
    // 简化实现:返回基本位置信息
    return artifacts.map(a => ({
      id: a.id,
      bytes: a.sizeBytes ?? 1024 * 1024,
      replicas: [{ deviceId: 'cloud-runtime', readMs: 10 }]
    }));
  }
  
  private buildNetworkTopology(devices: UnifiedDeviceProfile[]): any[] {
    // 构建设备间网络链路信息
    const links: any[] = [];
    
    for (const device of devices) {
      links.push({
        from: 'cloud-runtime',
        to: device.deviceId,
        bytesPerSecond: device.networkProfile.downloadMbps * 125000,
        fixedMs: device.networkProfile.rttMs,
        effective: true,
        source: 'REAL',
        observedAt: device.networkProfile.measuredAt,
        ttlMs: 30000
      });
      
      links.push({
        from: device.deviceId,
        to: 'cloud-runtime',
        bytesPerSecond: device.networkProfile.uploadMbps * 125000,
        fixedMs: device.networkProfile.rttMs,
        effective: true,
        source: 'REAL',
        observedAt: device.networkProfile.measuredAt,
        ttlMs: 30000
      });
    }
    
    return links;
  }
  
  private authorizePlacement(planResult: any, task: AITaskProfile): any {
    // 应用门禁策略:OBSERVE/SHADOW/CANARY/ACTIVE
    // 简化实现:返回实际选择
    return {
      actualDeviceId: planResult.suggestion.deviceId,
      actualExecutorId: planResult.suggestion.executorId,
      reason: planResult.suggestion.reason,
      mode: 'OPTIMIZED'
    };
  }
}
```

```typescript
import { hilog } from '@kit.PerformanceAnalysisKit';
import { SchedulerService } from '@智调鸿枢/scheduler';
import http from '@ohos.net.http';

export interface DeviceCapabilityDescriptor {
  capability: string;
  modelId?: string;
  modelVersion?: string;
  backend: string;
  quality: number | null;
  estimatedMs: number;
}

export class DeviceProfileUploader {
  private readonly TAG = 'DeviceProfileUploader';
  private uploadInterval: number = -1;
  private cloudEndpoint: string;
  
  constructor(
    private readonly schedulerService: SchedulerService,
    cloudUrl: string
  ) {
    this.cloudEndpoint = cloudUrl;
  }
  
  start(): void {
    // 首次立即上报
    this.uploadProfile();
    
    // 定时上报(每30秒)
    this.uploadInterval = setInterval(() => {
      this.uploadProfile();
    }, 30000);
  }
  
  stop(): void {
    if (this.uploadInterval !== -1) {
      clearInterval(this.uploadInterval);
      this.uploadInterval = -1;
    }
  }
  
  private async uploadProfile(): Promise<void> {
    try {
      const profile = await this.buildProfile();
      await this.sendToCloud(profile);
      hilog.info(0x0000, this.TAG, 'Device profile uploaded successfully');
    } catch (error) {
      hilog.error(0x0000, this.TAG, `Failed to upload profile: ${error}`);
    }
  }
  
  private async buildProfile(): Promise<Record<string, Object>> {
    const state = this.schedulerService.getCurrentState();
    const metrics = this.schedulerService.getMetrics();
    
    // 收集本设备支持的所有capabilities
    const capabilities = this.discoverCapabilities();
    
    return {
      deviceId: this.getDeviceId(),
      deviceType: 'PHONE',
      capabilities: capabilities.map(c => c.capability),
      
      resourceSnapshot: {
        availableSlots: this.schedulerService.getAvailableSlots(),
        totalMemoryMB: Math.round(state.totalMemoryMb ?? 0),
        availableMemoryMB: Math.round(state.availableMemoryMb),
        thermalLevel: state.thermalLevel,
        batteryPercent: state.batteryPercent,
        cpuUsagePercent: Math.round(state.systemCpuUsage)
      },
      
      hardwareProfile: {
        backends: state.availableBackends,
        cpuCores: undefined, // 可选:通过Native接口获取
        cpuArchitecture: undefined
      },
      
      networkProfile: {
        uploadMbps: this.estimateUploadSpeed(),
        downloadMbps: this.estimateDownloadSpeed(),
        rttMs: this.estimateRTT(),
        measuredAt: Date.now()
      },
      
      executionHistory: capabilities.map(cap => ({
        capability: cap.capability,
        sampleCount: cap.quality !== null ? 10 : 0,
        meanMs: cap.estimatedMs,
        p95Ms: cap.estimatedMs * 1.2,
        failureRate: 0.01,
        lastExecutedAt: Date.now() - 60000
      })),
      
      observedAt: Date.now(),
      ttlMs: 60000, // 60秒TTL
      source: 'REAL',
      trusted: true
    };
  }
  
  private discoverCapabilities(): DeviceCapabilityDescriptor[] {
    // 返回本设备实际支持的AI能力列表
    // 注意:这里不是写死购物相关能力,而是动态发现
    
    const caps: DeviceCapabilityDescriptor[] = [];
    
    // 检查本地是否有图像裁剪能力
    if (this.hasImageCropCapability()) {
      caps.push({
        capability: 'image.crop.v1',
        backend: 'CPU',
        quality: null,
        estimatedMs: 150
      });
    }
    
    // 检查本地是否有embedding模型
    if (this.hasEmbeddingModel()) {
      caps.push({
        capability: 'image.embedding.v1',
        modelId: 'mobilenet_v3',
        modelVersion: '1.0',
        backend: 'CPU',
        quality: 0.85,
        estimatedMs: 200
      });
    }
    
    // 检查本地向量检索能力
    if (this.hasVectorSearchIndex()) {
      caps.push({
        capability: 'vector.search.v1',
        backend: 'CPU',
        quality: 0.9,
        estimatedMs: 50
      });
    }
    
    return caps;
  }
  
  private hasImageCropCapability(): boolean {
    // 检查是否有ImageKit或类似能力
    return true; // 简化实现
  }
  
  private hasEmbeddingModel(): boolean {
    // 检查本地模型文件是否存在
    return false; // 需要根据实际情况判断
  }
  
  private hasVectorSearchIndex(): boolean {
    // 检查本地索引数据
    return false;
  }
  
  private getDeviceId(): string {
    // 返回唯一设备标识
    return 'phone-' + (globalThis.deviceId ?? 'unknown');
  }
  
  private estimateUploadSpeed(): number {
    // 从历史网络请求中估算上传速度(Mbps)
    // 简化实现:返回固定值
    return 10.0;
  }
  
  private estimateDownloadSpeed(): number {
    return 20.0;
  }
  
  private estimateRTT(): number {
    return 50;
  }
  
  private async sendToCloud(profile: Record<string, Object>): Promise<void> {
    const httpRequest = http.createHttp();
    
    try {
      const response = await httpRequest.request(
        `${this.cloudEndpoint}/api/v1/devices/register`,
        {
          method: http.RequestMethod.POST,
          header: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${globalThis.deviceToken ?? ''}`
          },
          extraData: JSON.stringify(profile)
        }
      );
      
      if (response.responseCode !== 200) {
        throw new Error(`HTTP ${response.responseCode}`);
      }
    } finally {
      httpRequest.destroy();
    }
  }
}
```

```typescript
import { TaskTemplate, TaskContext } from './SchedulerTypes';
import { SchedulerClient } from './SchedulerClient';

/**
 * 外部App通过此适配器接入调度系统
 * 不再写死购物/裁剪等具体业务
 */
export class ExternalTaskAdapter {
  constructor(private readonly schedulerClient: SchedulerClient) {}
  
  /**
   * 提交一个通用AI任务
   * @param capability 任务能力标识,如 'image.classification', 'nlp.translation'
   * @param modelRequirements 模型要求
   * @param context 任务上下文
   */
  async submitTask(
    capability: string,
    modelRequirements: {
      modelId?: string;
      modelVersion?: string;
      backend?: string[];
      minimumQuality?: number;
    },
    context: {
      userWaiting: boolean;
      userVisible: boolean;
      importance: number;
      budgetMs: number;
      inputData: ESObject;
    }
  ): Promise<ESObject> {
    // 构建任务模板
    const template: TaskTemplate = {
      id: capability + '-task',
      type: this.inferTaskType(capability),
      capability: capability,
      location: 'HYBRID', // 允许本地或远端执行
      qualityTiers: modelRequirements.minimumQuality 
        ? [modelRequirements.minimumQuality]
        : [0.5, 0.7, 0.9],
      modelRequirements: modelRequirements,
      pausable: !context.userWaiting,
      resumable: false,
      privacy: 'NORMAL',
      executorFilter: {}
    };
    
    // 构建任务上下文
    const taskContext: TaskContext = {
      userWaiting: context.userWaiting,
      userVisible: context.userVisible,
      importance: context.importance,
      targetResponseMs: context.budgetMs * 0.7,
      hardDeadlineMs: context.budgetMs,
      freshnessMs: 5000,
      inputScale: 1.0,
      networkAllowed: true,
      workflowRemainingMs: context.budgetMs
    };
    
    // 提交到调度器
    const result = await this.schedulerClient.submitWithWorkflow(
      template,
      taskContext,
      context.inputData
    );
    
    return result.value;
  }
  
  private inferTaskType(capability: string): string {
    // 根据capability推断任务类型
    if (capability.startsWith('image.')) return 'IMAGE_PROCESSING';
    if (capability.startsWith('nlp.')) return 'NLP';
    if (capability.startsWith('vector.')) return 'RETRIEVAL';
    return 'GENERIC_AI';
  }
}
```

## 三、调度算法统一

### 3.1 宏观调度:设备选择不区分来源

修改 `WorkflowPlacementPlanner`:
- 输入统一为 `UnifiedDeviceProfile[]` 候选列表
- 不再区分 Worker/Phone/Cloud 的特殊逻辑
- 只看:capability匹配、资源可用、数据位置、网络成本、历史性能

### 3.2 微观调度:设备内硬件资源分配

修改 `apps/harmony/scheduler`:
- `ConstrainedPolicy` 继续根据设备状态选择执行配置
- 新增 `HardwareProfileAdapter`:读取设备内可用硬件(CPU核心/GPU/NPU)
- 配置选择时考虑:线程数、内存分配、后端选择(CPU/GPU/NPU)

### 3.3 算法收敛流程

```
1. 云端收到AI任务请求
2. 查询 UnifiedDeviceRegistry,获取所有支持该capability的设备画像
3. 调用 WorkflowPlacementPlanner,输入:
   - 任务需求(capability, 资源, 预算)
   - 候选设备列表(来自注册中心)
   - 数据位置(artifact副本分布)
   - 网络拓扑(设备间传输性能)
4. 算法输出:baseline方案 + suggestion方案
5. 应用门禁策略(authorizePlacement)
6. 派发到选中设备,携带完整任务画像
7. 目标设备接收任务:
   - Phone: 通过HAR的ExternalTaskAdapter接入微观调度
   - Worker: 通过LeaseManager申请资源槽
   - Cloud: 由RuntimeRunner执行
8. 设备内部微观调度:
   - 检查资源准入(内存/槽位/热状态/电量)
   - 选择执行配置(线程数/后端/质量档位)
   - 队列排序,分配硬件资源
   - 执行任务,收集遥测数据
9. 执行完成后:
   - 上报执行遥测(实际耗时/资源使用/质量)
   - 更新设备画像中的executionHistory
   - 云端收集反馈,校准成本模型
```

## 四、关键修改点总结

### 4.1 需要删除/重构的硬编码

**删除:**
1. `ShoppingTaskService` 中的 `REMOTE_CLOUD` 固定声明
2. `DeviceDispatchService.crop()` 专门处理裁剪的方法名
3. `PhoneDispatchService` 的独立派发逻辑

**替换为:**
1. `UnifiedTaskSchedulerService.scheduleTask(AITaskProfile)` - 通用调度入口
2. `DeviceDispatchService.dispatch(capability, task)` - 根据capability动态派发
3. 将PhoneDispatch纳入统一设备注册,不再是单独机制

### 4.2 核心链路修改

#### 旧链路(购物专用):
```
ShoppingTaskService (写死REMOTE_CLOUD)
  → CloudShoppingExecutor
    → 云端Runtime
      → 12阶段串行
        → crop阶段: PhoneDispatchService(独立) 或 DeviceDispatchService(Worker)
```

#### 新链路(通用):
```
ExternalApp
  → 生成 AITaskProfile (capability + requirements)
    → UnifiedTaskSchedulerService
      → UnifiedDeviceRegistry.getDevicesForCapability()
      → WorkflowPlacementPlanner.plan() [统一算法]
      → 选中Device
        → Phone: ExternalTaskAdapter → HAR微观调度
        → Worker: HTTP派发 → LeaseManager
        → Cloud: RuntimeRunner
```

### 4.3 设备画像字段对比

| 字段分类 | 原架构 | 新架构 |
|---------|--------|--------|
| 设备标识 | deviceId | deviceId + deviceType |
| 能力声明 | 写死购物相关 | capabilities[] 动态列表 |
| 资源快照 | Worker有,Phone缺 | 统一resourceSnapshot |
| 硬件信息 | 散落各处 | hardwareProfile统一 |
| 网络性能 | 传输样本分散 | networkProfile统一 |
| 执行历史 | PerformanceRegistry | executionHistory[] |

## 六、关键技术决策说明

### 6.1 为什么不汇总所有设备硬件?

**错误理解:** 把A手机2核CPU + B手机4核CPU = 6核虚拟CPU池

**正确做法:**
- 宏观调度比较 **独立设备的整体能力**
- 每个设备是 **独立执行单元**,有自己的内存空间、进程隔离
- 算法选择"这个阶段在哪个设备上完成",不是"这个核心给哪个设备"

### 6.2 调度算法是否需要AI模型?

当前不需要。原因:
1. 硬约束(能力匹配/资源/隐私)已过滤大部分不可行方案
2. 成本模型基于实测样本的EWMA,可解释且可调试
3. 束搜索算法在有限候选下足够高效

未来可优化:
- 引入RL策略学习最优配置切换时机
- 但当前基于规则+统计的方法已满足需求

### 6.3 设备画像的TTL如何设定?

**建议:**
- Phone(移动): 30-60秒 (状态变化快,电量/热/网络)
- Worker(固定): 5分钟 (相对稳定)
- Cloud: 10分钟 (容量变化慢)

**机制:**
- 设备主动续约(定时上报)
- 云端被动过期(TTL超时删除)
- 任务派发前检查设备仍在线

### 6.4 如何处理capability版本演进?

**方案:**
- capability包含版本号: `image.crop.v1`, `image.crop.v2`
- 设备可同时支持多个版本
- 任务请求指定要求的版本范围
- 调度器匹配时严格检查版本兼容性

示例:
```typescript
// 设备声明
capabilities: ['image.crop.v1', 'image.crop.v2']

// 任务要求
capability: 'image.crop.v2'  // 只匹配v2

// 或
capabilityRange: { base: 'image.crop', minVersion: 1, maxVersion: 2 }  // v1和v2都可
```
