# 网络画像驱动调度：实施与验收

本次落实“主要缺口 1”：将网络画像从展示数据接入决策、执行和反馈。范围覆盖 harmony-agent 的手机 SDK、演示 App、API 服务和监控服务，以及 cixin-agent 的板端协调器、HTTP 传输、节点接口与调度盘。原有修改策略文档保持不变。

## 1. 已接通的链路

### Harmony

1. `SchedulerClient` 在提交调度任务前调用执行器的可选 `prepare(input, context, signal)`。App 适配器准备实际图片 Base64/文本负载，提交通用 `RemoteTaskProfile`；SDK 不检查购物操作名称。
2. SDK 的 `RemoteRouteRegistry` 管理候选画像、TTL、失效原因和按任务种类/输入模态/大小桶隔离的 EWMA 历史。`HttpRouteProbe` 是可复用的 Network Kit 适配器，endpoint、routeId、认证头由 App 提供。
3. 顺序探测 ping、小负载上传、下载、事件循环队列、远程依赖。探测接口不执行业务搜索。当前交互任务上传探测 32 KiB、下载探测 32 KiB。
4. `SemanticPolicy` 在选取质量档位和检查 deadline/freshness 时使用候选路由的总耗时预测。准备阶段耗时计入原始任务预算，最终 HTTP 超时也受剩余预算限制。
5. 执行器只接受计划中的有效路由：校验 provider、endpoint/网络代次和 TTL，不再在业务执行时临时创建全 null 路由，也不重复执行健康探测。
6. 手机将同一实测路由提交给 API；服务端验证来源、数值、授权和时间戳，以实际请求数据大小为上传下界。图片图只在入口节点计算手机传输成本，后续步骤明确标为 `in_process`。
7. 服务端冷启动不能豁免网络实测。计算历史不足时使用工具显式声明的计算先验；先验不是实测样本。网络和计算成本共同用于评分与时限约束。
8. 上传/下载进度通过可选 `onProgress` 回调进入调度日志；队列、计算耗时随服务端回执补齐，完成/失败事件进入日志。最终分段遥测有界提交并与 runId/taskId 关联。
9. 服务端返回真实执行耗时，手机即便缺少原生上传计时，也能按任务大小桶更新下一次计算预测。网络吞吐只有存在真实字节数与有效耗时才更新，不把总请求耗时伪装成 RTT。

### Cixin

1. `FleetRuntime.plan` 在获取远端报价并比较本地/其他开发板前，通过已登记 peer 的地址与 token 进行链路探测。
2. 调度使用实测 RTT、上行、下行。保守传输估算使用两方向较慢者；`PeerConfig.bytesPerSecond` 保留配置兼容性，但不再决定自动调度。
3. 探测失败、无探测实现、画像过期、报价拒绝均排除该远端。不会使用配置带宽掩盖探测失败。原有权限、模型兼容、样本门槛和未知执行状态规则仍然生效。
4. 节点报价提供队列与计算预测，真实回执继续训练已有放置模型。HTTP 下载读流反馈更新吞吐 EWMA，不刷新未测量的上行时间戳。
5. 板端沿用既有放置策略的 3 秒链路新鲜度门槛，缓存不足 2.5 秒才复用，并传递真实 sampleAgeMs。每次规划核对主机网络接口指纹（使用摘要，不向调度盘暴露接口地址）；超时、失联和失败使路由失效。执行阶段事件写入 run 审计。

## 2. 测量含义与边界

- RTT 是无业务 ping 请求的 HTTP 往返耗时，包含连接/协议成本，不是 ICMP RTT。
- 上下行初始值是小负载请求的有效吞吐下界，含协议开销，来源标为 `measured-effective-throughput`；不会声称是运营商标称链路容量。
- `minimal-task.queueMs` 是事件循环探测排队时间。模型供应商内部队列不可单独观测，其影响包含在执行耗时历史中。
- 当前服务端 Runner 没有独立入队等待，业务回执 `queueMs = 0` 表示此执行路径不设排队。它不代表外部模型没有排队。
- 费用依赖计费策略。没有可验证价格时 `costEstimate` 保留 null，服务端有费用上限的任务仍拒绝无法验证的费用；不会填假零元。
- SDK RTT/队列当前共用最短有效期；上/下行共用带宽时间戳，按上行更严格的 TTL 失效。交互任务 RTT 30 秒、带宽 60 秒、依赖 180 秒；实时 RTT 10 秒；后台采用更宽的带宽/依赖期限，但队列仍限制 60 秒。过期会重新探测，不延长旧观测时间。
- 手机通过 `GET_NETWORK_INFO` 权限监听网络可用、丢失、能力和连接属性变化；网络变更立即失效旧缓存并改变路由代次。监听不可用时每次提交强制重新探测。探测中切网最多重探一次；不重放业务请求。
- 手机 EWMA 与板端网络缓存当前驻留内存，重启后重新探测。Cixin 运行回执沿用本地 JSON 审计持久化；本次没有增加跨重启网络历史数据库。
- 当前购物 App 声明的是云能力，弱网下没有已注册的本地购物实现时会拒绝任务，而不会虚构本地模型。通用 API 调度器已验证本地/云端选路翻转；Cixin 已验证本地/边缘选路翻转。
- 健康检查的商品空库、向量完整性与按能力拆分仍属于原问题 5；本次复用现有依赖健康状态。Runtime 鉴权归属和后台停止确认也不在本次网络修复范围。

## 3. 接口与接入变化

API 新增：

- `GET /api/v1/runtime/probe/ping`
- `POST /api/v1/runtime/probe/upload`，仅接受有界测试字符串
- `GET /api/v1/runtime/probe/download`
- `POST /api/v1/runtime/probe/minimal-task`
- `GET /api/v1/runtime/probe/dependencies`

Cixin 节点提供已鉴权的 ping/upload/download 同路径接口；队列与能力状态来自现有 quote。

携带客户端 taskId 的购物任务现在必须提供有效 `networkProfile`。旧手机版本或手工脚本若仍提交 null 网络画像会被拒绝，应与服务端一起升级。通用执行器如需前置探测，可实现 `prepare`；无需此能力的原执行器仍可继续使用。

调度盘显示 RTT、有效上下行、传输/总耗时预测、TTL/失效原因，以及真实请求和阶段耗时。Harmony 监控服务白名单已同步，过滤 endpoint/networkKey、任意事件字段及凭据。

## 4. 自动化验收

- API 单测：网络证据缺失/声明值/过期/非法速率被拒绝；实测传输成本接入图片图且仅计算一次；弱网阻断业务副作用；改变真实带宽会改变本地/云端选择；探测负载有界。
- 手机 HTTP 回归：业务提交前只发送探测；业务请求携带实测画像；超时、HTTP 失败、过期与取消；准备阶段取消不提交任务、不向不存在的任务发信号。
- Cixin 回归：两个 HTTP 节点实际执行；弱网改变本地/边缘选择；失败不使用配置带宽；共享类型/策略一致；TTL、EWMA、任务桶隔离与缺失原生上传计时的服务端反馈。
- 监控回归：预测与实测能通过白名单，地址与任意附加字段被清除。
- DevEco 原生 HAP/HAR 构建和 scheduler/entry 原生测试；详细记录见 `verification/network-profile-native-build.txt`。产物未签名，未安装到真机。
