# Runtime 真实资源状态与阻断项

更新时间：2026-09-06

这份清单记录当前仓库能够证明的资源，以及还不能证明的资源。没有完成真实探测、授权或基准测试的能力，不会被 Scheduler 当作可用执行器。

## 已落地且可以验证的部分

- `ToolDescriptor`、`TaskIntent`、`TaskGraph`、`PlatformProfile`、`RuntimeState`、`ExecutionPlan` 和 `TelemetryRecord` 协议。
- Shopping Plugin 的 7 个业务工具注册。
- 任务依赖图的缺失依赖、重复 ID 和循环依赖检查。
- 隐私、位置、内存、模型支持、后端可用性、P95 时延、质量和能耗硬约束。
- 基于真实 Telemetry 样本的 P50/P95、质量、能耗和可靠性评分，以及切换滞回。
- 当前 Node 主机的 CPU 核数、总内存、空闲内存和 CPU 使用率读取。
- 缺少真实数据时返回 `blocked`，而不是选择一个经验后端。

## 当前明确缺失的资源

### 云端基础设施

- 云端数据库托管平台、实例地址、数据库名称、账号、密码和 TLS 配置。
- 对象存储平台、区域、Endpoint、Bucket、访问密钥和生命周期策略。
- 云端 API 网关或服务部署地址，以及网络、域名和证书配置。
- Agent Planner 所需的大模型平台、模型名称、API 地址、密钥、配额和超时策略。
- 视觉模型、聊天模型、Embedding 模型的真实供应商、模型名称、密钥和维度。
- 视觉、聊天、Embedding 供应商的真实健康检查和模型探测协议。

`CloudPlatformAdapterService` 当前会把云端执行器保持为不可用，即使环境变量写入了 URL、Key 和 Model。配置本身不是健康检查、模型探测或能力证明；必须先实现供应商级适配器并完成真实请求验证。

### 授权数据源

- 淘宝、抖音电商、拼多多、得物、京东等平台的正式授权 API、调用范围、限流和合规凭据。
- 商品池的确认来源、抓取/导入授权、数据更新时间和失效策略。
- 实时价格、库存、商品链接和历史价格的可验证数据源。

未提供上述授权时，不能把商品池样例或本地测试数据宣称为实时平台结果，也不能启用 marketplace 执行器。

### HarmonyOS、CIX P1 与模型运行时

- HarmonyOS/CIX P1 真机或开发板、系统版本、连接方式和 SDK。
- CPU/GPU/NPU 的真实设备信息与统一适配器实现。
- NeuralONE、MindSpore Lite 或其他实际采用的模型运行时版本。
- GPU/NPU 支持的模型文件、算子支持矩阵、INT8/FP16 能力、输入尺寸和 CPU fallback 结果。
- 模型加载、推理、取消、检查点和执行结果回传接口。

目前 HarmonyOS 和 CIX P1 适配器只会返回 `*_DEVICE_ADAPTER_NOT_CONNECTED`，不会伪造硬件能力。

### 动态硬件与网络监测

- GPU/NPU 利用率和队列长度接口。
- 温度传感器和热降频状态接口。
- 电池电量、电源状态和充电状态接口。
- 磁盘剩余空间、网络吞吐、网络延迟和丢包率接口。
- 运行时活动任务计数器和跨阶段取消/恢复信号。

当前主机适配器只能证明 CPU、内存和 CPU 使用率；其余缺失指标会以不可用状态返回。未观测到的指标不会被填入默认值。

### 真实性能档案

每个工具、执行器和模型组合都需要在目标设备上采集至少配置的最小样本数，并记录：

- P50/P95 延迟。
- 峰值内存。
- 能耗和温升。
- 任务质量指标，例如识别置信度、Recall@K 或相似度。
- 失败率、fallback 次数和成功率。
- 输入尺寸、模型版本、运行时版本和设备标识。

当前性能档案只在进程内由 Telemetry 累积，没有持久化基准库；没有样本的候选会被硬性淘汰。

## 仍未实现的运行能力

- 真实 Agent Planner 注入和目标到 TaskGraph 的模型调用。
- 执行器调用层：目前 Runtime API 生成并验证计划，不替业务模块执行实际模型或网络任务。
- 阶段级 checkpoint、取消、恢复、降级后的实际重试和迁移。
- 持久化 Telemetry、跨进程性能学习和审计日志。
- Provider-specific Cloud、HarmonyOS 和 CIX P1 Platform Adapter。

这些能力缺失时，API 会返回阻断原因；不能用固定 CPU/GPU/NPU 链条替代。

## 处理顺序

1. 确认云端数据库、对象存储、模型 API 和授权电商 API。
2. 提供目标设备、SDK、模型文件和运行时版本。
3. 实现并验证各平台的静态能力、模型能力和动态状态采集。
4. 在目标设备上采集性能样本，再启用 Scheduler 评分和滞回。
5. 接入真实 Agent Planner 和执行器，补齐 `plan -> execute -> observe -> verify -> replan` 闭环。

在第 1 至第 4 步完成前，当前项目只能作为 Runtime 协议和阻断逻辑测试应用运行。
