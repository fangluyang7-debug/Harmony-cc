# 主创新专题：面向 P1 设备能力的端云技能编译

更新日期：2026-09-17。性质：已纳入 [作品设计 V2](26-参赛作品设计-通用端云协同Runtime.md) 与 [架构 V2](27-端云模型分工与项目架构图.md) 的主创新专题，尚未实现。两份 V2 主文档为协作者的统一范围与验收依据，本文补充原理、边界和相关研究；不与所有增强项同时扩张。

## 1. 核心概念

将经过验证的云端任务规划，转换为 P1 可以解释执行的参数化技能。后续在适用范围内的新任务复用执行方法，重新处理实际输入，减少重复云规划。技能不适用、依赖变化或执行验证失败时，停止复用，回到正常规划路径。

作品叙述可用：**让云端规划成果沉淀为经过验证的端侧执行能力。**

这里的“编译”是从 TaskGraph 转换为受限、可校验、可执行的流程描述，不是把大模型权重转换成小模型，也不是把云推理能力无损搬到本地。

## 2. 为什么适合当前项目

已有 TaskGraph、工具注册、调度评估与运行轨迹，可作为编译输入和执行基础。新增部分聚焦于图参数化、依赖校验、技能存储与选择；不需要训练基础模型或部署多板集群。

它为框架增加一个随使用积累的资产：经过验证的任务技能。应用插件负责语义和工具，通用核心负责技能生命周期和设备适用性。

必须先完成真实 DAG Runner 和执行结果记录。只有调度动画，不能产生可信的技能来源。

## 3. 完整流程

```text
新任务
  → 没有适用技能
  → 云端规划 + P1 校验并执行
  → 任务结果通过验证，记录实际执行轨迹
  → 提取参数化技能候选
  → 结构、数据政策、工具与模型依赖校验
  → 使用独立样例进行本地试运行
  → 通过后加入技能库

后续任务
  → 识别任务类型并绑定参数
  → 检查适用范围、工具版本、模型和索引兼容性
  → 当前 Scheduler 重新绑定可用执行器
  → P1 解释执行技能，重新计算结果
  → 验证通过则返回；失败则停用或退回规划
```

不能因为一次成功就永久启用技能。成功轨迹只产生候选，需要变化输入和反例测试。

## 4. 购物示例

首次目标：“根据照片找同款鞋，42 码、500 元以内。”

云端生成计划，P1 执行本地特征提取、索引召回、身份与条件核验；困难分支可能调用云复核。任务完成后，系统提取候选技能：

```text
技能：按图检索并按条件筛选鞋类候选
参数：image, size, maxPrice
依赖：图像编码工具、兼容索引、条件筛选与身份验证工具
本地路径：编码 → 召回 → 条件过滤 → 身份验证 → 输出
异常出口：证据不足时补充数据、请求云复核或等待用户
```

后续换图片、改成 41 码与 400 元，系统重新提取特征、查询数据并验证结果；保存的是流程，不是第一次的商品答案。

若款号证据充分且所有必要工具本地可用，可以跳过云规划并走完本地路径。若仍需云视觉复核，只节省规划调用，不能宣称整次任务已经离线完成。

无联网时只能基于本地数据或明确标注的快照；技能复用不创造实时价格、库存或缺失的模型能力。

## 5. 区别在哪里

| 相邻机制 | 本方案的明确目标 |
|---|---|
| 答案缓存 | 对新图片与新条件重新执行工具，不复用过期商品答案 |
| 对话记忆／经验提示词 | 保存可执行流程及适用条件，命中时无需每次由云模型重新解释整套流程 |
| 人工固定模板 | 从实际运行轨迹产生候选，自动检查并形成可管理资产；仍应与人工模板比较 |
| 普通流程重放 | 参数化新输入，并检查设备能力、模型／索引版本和业务前置条件 |

性能不应预设优于优秀的人工模板。相对人工模板的潜在价值主要是减少新流程的人工配置与维护成本，需记录实际编辑和审核工作量验证。

## 6. 最小技术实现

新增四个模块：

1. `SkillCompiler`：从已验证图和实际轨迹提取参数、步骤与允许的分支。
2. `SkillValidator`：检查图结构、工具契约、适用范围、数据政策和运行依赖，并执行测试。
3. `SkillRegistry`：存储技能版本、来源 run、验证记录、停用原因和依赖信息。
4. `SkillResolver`：将新目标匹配到候选技能，校验参数与前置条件；通过后交给原 Runner。

技能最小字段：

```text
skillId / version / sourceRunIds
intentType / parameterSchema / preconditions
taskGraph / outputValidators / fallbackPolicy
toolVersions / modelRevision / preprocessingVersion / indexCompatibility
dataPolicy / validationRecord / status
```

首版只支持注册工具组成的 JSON 图、有限条件分支和有界重试。不执行云端任意生成的 Python、Shell 或下载代码。

参数化规则由工具 schema 与插件元数据明确声明。不能让模型任意把“500 元”“42 码”和商品身份字段都替换成参数，也不能把隐含限制误删。

技能保存逻辑依赖，Scheduler 每次依据当前 P1 能力选择执行实现；不永久保存一次运行时的 GPU/NPU 分配。

## 7. 适用性与失效机制

- 意图匹配：首版限制 2～3 类已支持任务。规则可解析的表达直接绑定参数；未知表达退回云理解，或允许用户选择技能后填参数。不得声称已具备通用离线自然语言理解。
- 参数检查：类别、字段类型、范围和必要输入全部满足才可执行，不能只靠语义相似度命中。
- 依赖检查：工具 schema 或模型预处理不兼容时停用或重新验证。索引内容正常更新不必一律停用，按插件定义的兼容契约检查。
- 执行验证：输出仍逐次验证，历史成功不能代替当前检查。
- 恢复：停止不适用路径，复用仍有效的中间产物，重新规划或报告限制。

首版采用只读检索／报告工具，避免把外部不可逆动作纳入自动复用范围。

## 8. 什么是拟议差异，什么不能声称首创

[Agent Workflow Memory](https://arxiv.org/abs/2409.07429) 已研究从经历中提取可复用工作流；[ReUseIt](https://arxiv.org/abs/2510.14308) 已研究从执行尝试合成带执行检查的可复用流程。因此，“技能库”“从经验复用流程”“失败检查”都不能单独声称是本项目首创。

本项目应把创新主张限定为拟实现与实测的组合：**面向 P1 本地模型及工具契约，将云规划图转为参数化执行技能，通过设备能力与模型／索引兼容性检查控制启用，并在新任务上评估减少云规划依赖的收益。**

本次检索不足以证明这一组合在学术或专利意义上无人做过。适合作为赛事的系统设计创新候选；如果比赛要求原创算法，还需进一步文献对照和明确算法贡献。

## 9. 验证设计

分开用于技能生成、调试与最终评估的样例，评估集中包含新图片、不同预算尺码、无匹配、类别越界和依赖变化。不能用原输入的第二次运行证明泛化。

三组对照：

- 每次云端重新规划。
- 人工预设同等能力的任务模板。
- 云端经历生成并验证的技能。

条件保持：同一工具／模型版本、相同数据与目标质量标准；冷启动和热运行单列。

指标：目标完成率、错误技能匹配率、边界情况拒用情况、每任务规划调用与 token、端到端时延，以及新技能的人工配置／审核工作量。

计算总成本时包含首次技能提取、试运行和失败回退开销。只有后续累计节省超过这些额外开销，才有成本上的收益；不能只展示命中后的单次低成本。

## 10. 适合初选的演示

1. 展示空技能库，对一个支持的任务进行真实云规划和执行。
2. 展示生成的候选技能及验证结果，明确验证过程不能省略。
3. 使用此前未见的新图片和不同参数，命中技能并重新执行，显示规划云调用被跳过。
4. 输入超范围任务或改变工具兼容条件，展示技能被拒用并退回规划。
5. 若演示断网，只选择所有必要工具与数据都在本地的路径；真实标注使用的数据快照。

最终申报句式建议：

> 本项目探索将云端规划成果转化为经过 P1 能力约束与样例验证的本地执行技能，使端云协同从逐次调用扩展到可复用流程的积累，并通过失效检测与重新规划维持执行边界。
