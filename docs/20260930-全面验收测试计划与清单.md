## 1. 环境与证据规则

- A：MIS-AL00，HDC `3YZ9K24B19003469`，发起购物和派发；B：ADY-AL00，HDC `2YB0224508010694`，接取计算任务。只操作独立测试包 `Micro.12.myapplication.codextest`，保留原版。
- 云端 API：`https://cixin.zeabur.app`。先核对部署、能力、商品目录和模型探针，再提交有限的测试请求；不得把 health 200 解释成业务成功。
- 电脑调度盘：在电脑运行 `npm run monitor:dev`，浏览器打开 `http://localhost:8765` 并用本机配对码连接；A 通过 HDC `rport tcp:8766 tcp:8765` 向电脑上报。**仪表盘截图必须由电脑浏览器直接截取**，不得用手机页面或旧示例图替代。
- 每项登记步骤、预期、实际、状态（通过／失败／阻塞／未执行）、时间、任务与运行 ID（有则记）、证据文件。手机截图由 HDC 当前屏幕采集，电脑截图由桌面浏览器采集；不以旧轮次截图冒充本轮。
- 配对码、令牌、密钥、私人相册、完整商品图片和无关账号信息不进入可提交报告。现场截图先检查后入文。执行中的故障样本保留在失败分母；性能仅记本轮样本，不宣称普遍收益。
- 用户所说“文字识别”按当前代码的自然语言需求解析／文字商品检索核对；若作品没有独立 OCR 入口，不把 OCR 写为已实现。图片识别须查看真实视觉阶段和商品结果，不能只截图系统选图器。
- **视频放行门槛**：A 真机文字检索成功；A 选已知商品图、B 真机完成裁剪、云端完成图片检索、A 展示结果；电脑调度盘同次显示实时快照与任务/运行关联；取消回执终态明确。任何一环失败均不得写“可稳定演示”，先修复并重复复测。

## 2.1 调度件专项对照与压力矩阵（优先于界面展示）

以下每项同时保存输入状态、可用执行后端、候选档位、决策理由、实际执行、终态与耗时。真机硬件只报告系统公开 API 实测到的能力；注入状态和隔离回放标为“合成场景”，不得冒充设备真实发热、电量或 GPU/NPU 运行。

| ID | 调度层 | 场景 | 对照和判定 |
| --- | --- | --- | --- |
| ALG-01 | 微观 | 前台搜索独占 CPU | 相同语料直接执行（无调度）与经调度执行，交错顺序多轮；核对结果集合、成功率、P50/P95、排队、实际配置，不以一次胜负下结论 |
| ALG-02 | 微观 | 前台搜索与后台分块竞争 | 固定后台索引负载；比较前台响应、后台进度、让出/检查点、是否饥饿；失败与取消纳入分母 |
| ALG-03 | 微观 | 固定高性能／省电／自适应 | 同查询、相同真实设备状态、轮换顺序；核对实际执行 profile，模式标签本身不代表真实线程数或功耗 |
| ALG-04 | 微观 | 低电量、热压力、内存压力、未知值 | 隔离状态注入与原生规则测试；检验质量底线、保护阈值、保守降档和拒绝非法后端 |
| ALG-05 | 微观 | CPU/GPU/NPU/云端能力与隐私 | 核对 manifest、设备可用后端、任务语义和隐私约束；若真机只暴露 CPU，则 GPU/NPU 不作真机切换“通过” |
| ALG-06 | 微观 | 截止时间、队列、预算和取消 | 有界并发、前台优先、截止期、取消不提前释放槽位；用现场队列加隔离并发测试交叉验证 |
| ALG-07 | 微观 | 网络弱/断、画像过期、模型不可用 | 实测断网/重连并用回放注入 RTT、带宽/时效；核对本地/云决策与失败降级，不把 DNS 故障当模型故障 |
| ALG-08 | 宏观 | A、B、云三候选放置 | 记录任务能力、数据所在、上传/下载、B 在线与容量租约、云基线、剩余时限，核对选择理由和实际执行端 |
| ALG-09 | 宏观 | B 停轮询、忙、撤销与恢复 | 排队不误报完成；恢复后领租约，同一任务只结算一次；容量/epoch/迟到回执在隔离回归覆盖 |
| ALG-10 | 宏观 | B 执行中取消 | 必须看到停止请求、B 停止回执、A 的 CANCELLED_SETTLED；超时和取消不得伪装成执行已停止 |
| ALG-11 | 端到端 | 云端任务分阶段与电脑遥测 | 以同一 task/run/job ID 串联 A、B、云和 PC；截图必须能区分手机实际、电脑 Web 实际与概念架构图 |
| ALG-12 | 性能比较 | 调度劣势分析与修复回归 | 相同负载与质量条件下，如果调度导致可重复的额外排队或更高失败率，定位策略/测量原因；修改后复跑原样本。无法证明公平对照时写“尚无性能结论” |

## 3. 执行顺序与报告准则

1. 固定版本和安全配置，建立双机、云端及电脑遥测连接；先截电脑调度盘的实时状态。
2. 测试 App 导航、文字购物、会话操作，再测图片与双机计算；每个业务请求核对手机、电脑和云端的 ID/终态。
3. 测试调度与停止/恢复，运行隔离回归；可能造成在线数据更改或大量付费模型调用的项目采用小样本，不能无条件进行。
4. 依据本矩阵逐项出具“通过／失败／阻塞／未执行”，没有截图时注明原因与替代证据。报告附截图索引、环境复现步骤、缺陷及未覆盖项，不把自动化回归写成真机通过。
