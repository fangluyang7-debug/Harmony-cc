# 能力包参考用例

协调器使用已安装的参考包评估执行器。每个用例记录输入、参数、执行配置、覆盖维度和预期结算。修改期望答案、覆盖维度、拒绝码或不变量版本会改变套件摘要，触发重新评测。

| 内置包 | 检查内容 |
| --- | --- |
| text.count.v1 | 比对码点、空白分词和换行计数。覆盖空串、组合字符、CRLF、8 MiB JSON 输入上限、拼接文本以及非 JSON 拒绝。 |
| vector.normalize.v1 | 校验维度、每行方向、单位长度和输入范数。覆盖零向量、空行集合、大数、维度上限和非法行维度。 |
| image.crop.v1 | 使用独立生成的彩色图片检查 JPEG 格式、输出尺寸和像素颜色。覆盖左右贴边、填充、尺寸与质量参数的最小值及最大值，以及空字节和非法图像。 |

精确比较和性质检查取 0 或 1。容差评分取 0 至 1，由各包声明通过阈值。裁剪包按颜色误差范围内的像素比例计分。非法输入只有在执行器确认失败、没有输出且错误码符合契约时才得分。资源不可用、取消和结算不明会进入重试。

参考实现与设备执行器位于不同包中，架构检查禁止参考包导入执行器实现。两份实现仍可能有相同的理解偏差，特别是 Unicode 计数、浮点精度和图片缩放边界。外部模型质量需要各自的向量答案、模型清单和真实设备结果。

旧版图像编码套件已经以模型清单、输入摘要及期望向量生成套件身份，可以沿用原有文件。新编写的编码套件设置 `coverageVersion` 为 1，正例提供 `covers` 和 `vector`，反例提供 `covers` 和 `rejectCode`，并至少用一个正例验证 `model:manifest`。新格式缺少必需覆盖时，协调器拒绝装载。

协调器的生命周期隔离测试可以显式声明 `simulationFixture`，只在 SIMULATED 域使用。这类夹具验证重试和状态转换，不能作为能力包结构覆盖的证据。
