# Harmony 云端与本地协调时延实测及路演建议

测试日期：2026-10-31。分支：`codex/latency-cloud-vs-local`。业务基线：`2b6159e8866af7b123f52bf3285f198785a2663a`。

## 结论与方案建议

当前网络下，美西 Railway 云端链路的开销足以影响“点击后迅速响应”的演示。建议把**现场局域网中的指定电脑协调器作为决赛主链路的优先验证方案**，保留云端用于异地加入和云端模式演示。尚没有第二台电脑，不能据本次回环测试宣称局域网方案已经验收。

产品方向建议支持同一套协调服务的云端部署与本地部署：每个空间明确选择一个权威协调中心；本地模式仍统一指挥所有设备，不是每台设备各自独立决定团队任务。若未来叠加云端账号、空间管理与本地调度，属于需要实现的组合架构。本轮没有实现自动主节点选举、云边同步、离线权限或故障自动切换。

不建议只因这次结果否定所有云端方案：当前实例在美西，网络入口会变化；云端适合的任务粒度与低延迟交互不同。应另测更近部署区和真实耗时任务的总收益，不能将单次网络 RTT 直接当作任务总时延。

### 连续提交不能忽略资源状态刷新

任务前等待目标可用单独列出，未计入上表的提交后时间；右两列包含此等待。等待包含至少一次仪表盘读取，因此云端也含该次网络往返。当前代理 2 秒采样；任务已结束但上次占用信息尚未刷新时，快速提交可能遇到 NO_AVAILABLE_TARGET。本次正式组选择等待可用后提交，没有自动重试已失败任务。

| 小文本 | 14.56 / 26.58 | 397.48 / 768.30 | 660.22 / 726.69 | 4241.07 / 5238.54 |
| 256 KiB 文本 | 83.87 / 1960.18 | 1104.49 / 2610.07 | 763.18 / 2618.89 | 6749.30 / 14984.33 |

将协调器搬到本地，不能独自解决采样、状态更新、轮询和子进程启动开销。当前网页每 2.5 秒刷新；实际观看延迟还取决于轮询相位与请求时间。本实验没有把网页渲染耗时混入后台结果计时，也没有把 2.5 秒硬加到每个样本上。

## 环境与公平性边界

- 采样区间：2026-10-31T02:23:54.348Z 至 2026-10-31T02:33:41.647Z（UTC）。
- 本机：Intel(R) Core(TM) Ultra 7 155H，22 个逻辑 CPU，约 31 GiB 内存，Windows，Node v22.18.0。活动物理网卡为 Intel Wi-Fi 6E AX211；观测链路协商速率 480 Mbps，这不是公网可用带宽。
- 云端：https://harmony-space-production.up.railway.app，实际部署区 `railway/us-west2`；正式样本中的边缘入口标识：`cdg1`。边缘入口不等于部署区。
- 本地：独立协调器进程、独立数据库与 TLS，在 127.0.0.1 上运行；代理、客户端和协调器共享一台物理电脑。没有第二台设备、没有测真实局域网传输，没有测试手机或 GPU。
- 两组均使用相同 CPU 代理、1 CPU 槽位、256 MiB 贡献上限、REAL 域和同一任务输入。没有移除协议或 TLS 校验。
- 三轮顺序为本地→云端、云端→本地、本地→云端；每组每类任务预热一次，任务串行。后台负载和公网路由未固定，云端机器与本地硬件也不同，因此差值不完全等于网络开销。
- 初始化分别记录：本地配对 250 ms、能力就绪 6194 ms；云端配对 1323 ms、能力就绪 13630 ms。各仅一次，不能据此推断初始化分布。
- P95 使用 nearest-rank；15 个任务样本的 P95 是最大值，3 个暂停样本也是最大值。三轮密集样本不覆盖早晚高峰、赛场拥塞、掉线重连或多设备竞争。

## 路演前应做的下一步

1. 借到第二台电脑后，使用同一套案例测真实局域网：A 作为协调器/控制台，B 作为执行设备；再测 A、B 都连接 Railway。至少记录无线网络、设备位置、后台负载，重复多个时段。
2. 优先修正任务结束后的资源状态刷新和连续提交体验。目标是任务结束即及时更新可用状态，按钮即时反馈排队/执行进度；先定好产品体验目标再验收。
3. 评估合并串行请求、工件本地直连或缓存、执行进程复用、任务事件推送。它们可能同时改善本地与云端，不能靠改标签冒充性能提升。
4. 为决赛准备明确的本地模式启动、设备邀请、同局域网接入和展示入口。云端模式作为另一个已配置场景；尚未实现共享状态与故障接管时，不宣称两者能无缝切换。
5. 若坚持纯云端作主链路，先在独立测试服务验证更近区域，再复测完整任务与现场网络。Railway 官方列有新加坡等区域，但带卷服务改区会涉及迁移，因此本轮不移动正式实例。[区域说明](https://docs.railway.com/deployments/regions)
6. 加入真正有计算量的演示任务，验证节约的执行时间是否超过调度和传输成本。当前文本/向量案例用于测链路，不能证明团队算力加速收益。
